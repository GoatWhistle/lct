Сквозная идея повествования

Три акцента, в этом порядке. Каждый свободный слайд работает на один из них.

  • Тренажёр занятия, а не одного оператора. Все делают «курсант + звонок + балл». У нас в центре преподаватель: выдаёт карточки по уровням, вмешивается в ход, утверждает эталоны, ведёт разбор; группа видит итоги на внешнем мониторе. Это дословные формулировки ТЗ.
  • Оценка без чёрного ящика. Баллы считает код: факт против норматива со ссылкой на первоисточник (ГОСТ Р 22.7.03-2021, ПП РФ № 1931, памятка АРМ-112, классификатор ЕКП v046.24). Не «мы придумали шкалу», а «взяли норматив, по которому этих специалистов аттестуют». LLM баллов не ставит.
  • Материал заказчика, инженерная честность. 96 вызовов из 32 экзаменационных билетов жюри, сверено со сканом. Всё офлайн, на CPU, с нагрузочными и отказовыми испытаниями. Каждая цифра на слайдах имеет протокол проверки в репозитории.

Голос заявителя подаём одной строкой как дополнительный режим. По полю конкурентов голосовой контур есть у четырёх команд — это больше не отличие, строить на нём подачу нельзя.

Коротко о решении

по шаблону
Техническая суть
Веб-тренажёр: АРМ диспетчера ДДС, АРМ оператора 112, пульт преподавателя, внешний монитор аудитории. Маркетинговая суть
Учебные центры ГО ЧС получают то, чего по ТЗ «не существует»: тренажёр штатного ПО системы-112 с объективной оценкой. Разворачивается в LAN учебного класса одной командой, без интернета, лицензий и облаков. Контент — готовые экзаменационные билеты заказчика: преподаватель начинает занятие в день установки.

Оценка: баллы считает код — слайд-ров

Содержимое
Каждый балл — «факт против норматива со ссылкой». Таблица нормативов: ответ на вызов ≤8 с и опрос ≤75 с — ГОСТ Р 22.7.03-2021; решение ДДС ≤30 с — ПП РФ № 1931 и памятка АРМ-112; ошибки — поимённо из памятки. Таймеры останавливаются событиями, а не таймаутами — метрику можно предъявить. LLM-судьи нет. Итог преподаватель может скорректировать — правка уходит в аудит. Формулировка: «Мы не изобретали критерии — взяли нормативы, по которым этих специалистов аттестуют». Подача как добавленная ценность: ГОСТ в ТЗ не назван, требование ТЗ — «объективный контроль и оценка».
Визуал
Макет отчёта: строка метрики → факт (мм:сс) → норматив со ссылкой → статус цветом → код ошибки → рекомендация. Крупно: «ни одной отметки без обоснования». Основа макета — живой отчёт со стенда, не рисованная таблица.

Чего на слайдах НЕ заявлять

  • Голос заявителя «end-to-end работает» — распознавание речи в бою не гоняли. Формулировка только «дополнительный режим», без демо-обещаний.
  • Норматив оповещения ДДС 60 с — таймер в оценку не идёт, в таблицу нормативов не включать. Только 8 с / 75 с (ГОСТ) и 30 с (ПП № 1931).
  • Windows — не проверялся, не упоминать как готовое.
  • «Точная копия АРМ заказчика» — говорить «повторяет референс», не «пиксель в пиксель».
  • Сравнения с конкурентами по именам — на слайдах никаких чужих команд. Превосходство подаётся через первоисточники нормативов и протоколы испытаний.
  • Любая цифра не из этого брифа — сверить с командой: все приведённые здесь взяты из протоколов проверок в репозитории.

Визуальные принципы

  • Главный актив — живые скриншоты продукта. Не мокапы и не иконки: у сильнейших соперников в презентациях будут схемы, у нас — работающие экраны. Скриншоты дать в полном размере, обрезать без масштабирования вниз до нечитаемости.
  • Одна мысль — один слайд. Заголовок слайда формулирует вывод, а не тему («Баллы считает код», а не «Система оценки»).
  • Цитаты ТЗ — визуальный приём. Везде, где закрываем дословное требование, цитата в кавычках со ссылкой «— из ТЗ задачи №9». Жюри — авторы этих формулировок.
  • Везде образцовое прохождение. Во всех кадрах и схемах статусы только ok. Единственное исключение — отчёт на слайде 16: там warn/violated показывают, как система ловит ошибку условного курсанта, с подписью именно об этом. Это витрина оценки, а не недостаток продукта. Акценты шаблона — для навигации и заголовков.
