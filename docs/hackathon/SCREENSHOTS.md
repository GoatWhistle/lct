# Скриншоты со стенда

Список съёмки для презентации (бриф — [presentation-brief.html](presentation-brief.html)) и доп. материалов сдачи.
Снимаем с `make demo` после `make users` и `make seed`; ссылки на экраны печатает `make lesson`.

## Подготовка стенда

- Запущенное занятие по реальному билету (не «Вводный блок»), в очереди 2–3 карточки: так на реестре видны и новая карточка с таймером, и карточки в работе.
- Основной прогон — образцовый: нормативы соблюдены, во всех кадрах кроме `s16-report` только `ok`, никаких warn/violated.
- Отдельный прогон с нарушениями (просрочить 30 с, пропустить статус) — только для кадра `s16-report`: там ошибки условного курсанта — демонстрация контроля, это витрина оценки, а не недостаток продукта.
- Один непрофильный вызов из билета — для кадра мотивированного отказа (отказ с причиной — правильное действие, не ошибка).
- Учётные записи из demo seed, никаких реальных ФИО и телефонов.

## Правила съёмки

- Окно браузера 1920×1080, масштаб 100%, без панели закладок, DevTools и расширений.
- Курсантские экраны снимать под ролью курсанта: на них не должно быть `facts` и `ground_truth` — это одновременно проверка, что эталон не течёт.
- PNG без пережатия, имена файлов — по номерам ниже (`s14-dds-registry.png`).
- Ничего не ретушировать: казённый вид экранов — часть подачи, перекрашивать под палитру шаблона нельзя.

## Чего в кадрах быть не должно

- `facts` / `ground_truth` на экранах курсанта.
- Реальные ФИО, телефоны, адреса вне данных билетов.
- warn/violated где-либо, кроме кадра `s16-report`.
- Консоль браузера, ошибки JS, локальные URL с нестандартными портами в адресной строке крупным планом.
- Экранов голосового контура с заявителем как «работающей функции» — только кадр d09 с подписью про дополнительный режим.
