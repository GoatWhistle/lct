# Контракт фронтенда и бэкенда

← [PLAN.md](../PLAN.md) · [BACKEND.md](BACKEND.md) · [FRONTEND.md](FRONTEND.md)

Единственный шов между треками. Фиксируется **15.09 в первые три часа, до кода** — архитектура и фронт пишут его вдвоём и не расходятся, пока не подписан список событий и модель КИО. После этого меняется только явным уговором двоих.

**Источник истины — Pydantic-модели в `backend/app/domain/`.** `make types` гоняет их через JSON Schema в `frontend/src/shared/types/generated.ts`. Скрипт на 20 строк, окупается на второй правке контракта. Если генерация не заводится за полчаса — типы пишутся руками, но тогда любая правка модели на бэке обязана прийти в PR вместе с правкой TS.

---

## Четыре канала

| Канал | Кто | Направление | Что несёт |
|---|---|---|---|
| `WS /ws/call/{session_id}` | курсант-оператор 112 | дуплекс, бинарь + JSON | Аудио в обе стороны, события звонка, правки КИО |
| `WS /ws/station/{session_id}?role=dds_01` | курсант-диспетчер ДДС | дуплекс, **только JSON** | Карточка от оператора, подтверждение, отметки времени |
| `WS /ws/observe/{session_id}` | внешний монитор, пульт преподавателя | только приём, JSON | Зеркало состояния сессии без аудио |
| `WS /ws/control/{session_id}` | **только преподаватель** | только передача, JSON | Директивы звонящему, управление ходом занятия |
| `HTTP /api/*` | все | запрос-ответ | Сценарии, сессии, история, отчёты, генератор, аналитика |

**Разделение прав — архитектурное, а не дисциплинарное.**

- У внешнего монитора нет ни аудио, ни канала записи вообще. Он физически не может повлиять на занятие.
- Преподаватель смотрит через `observe` и пишет через `control`, и это **разные сокеты**. В `control` нет ни одной команды, меняющей карточку курсанта: преподаватель управляет ситуацией, а не работой обучаемого. Иначе оценка курсанта перестаёт быть его оценкой.
- У станции ДДС нет аудио — значит нет ни VAD, ни STT, ни TTS. Голосовой контур она не трогает, и это делает цепочку 112 → ДДС дешёвой на бэкенде.

## Аудио по WebSocket

**Бинарные кадры, без обёртки JSON.** Направление определяется каналом.

| | Курсант → сервер | Сервер → курсант |
|---|---|---|
| Формат | PCM16 моно | PCM16 моно |
| Частота | **16 000 Гц** (требование GigaAM) | **24 000 Гц** (выход Silero v5) |
| Кадр | 20 мс = 320 сэмплов = 640 байт | чанк по предложению, переменный |

Ресемплинг в 16 кГц делает фронт в AudioWorklet — не сервер. Так с микрофона не летит 48 кГц лишнего трафика, и сервер получает ровно тот формат, который ждёт модель.

Воспроизведение TTS — **очередь `AudioBufferSourceNode`, не `<audio>`**. Это не стилистическое предпочтение: barge-in требует оборвать звук мгновенно, а `<audio>` так не умеет.

## События: сервер → курсант

| Событие | Payload | Когда |
|---|---|---|
| `call.incoming` | `{scenario_id, caller_number, level}` | Преподаватель запустил сценарий. UI показывает входящий вызов |
| `call.started` | `{started_at}` | Курсант принял. Пошёл таймер опроса |
| `stt.partial` | `{text}` | Промежуточная расшифровка речи оператора |
| `stt.final` | `{text, at}` | Финальный чанк после endpointing |
| `caller.utterance` | `{text, at}` | Что сказал звонящий — текстом, синхронно с аудио |
| `tts.begin` / `tts.end` | `{utterance_id}` | Рамки реплики звонящего: UI гасит индикатор «говорит» |
| `tts.cancel` | `{utterance_id, reason: "barge_in"}` | Оператор перебил. **Фронт мгновенно чистит очередь** |
| `kio.patch` | `{fields: {...}, source: "auto"\|"operator"}` | Сервер сам распознал факт из речи либо эхо чужой правки |
| `timer.tick` | `{timers: [{code, elapsed_ms, limit_ms, state}]}` | Раз в секунду. `state`: `ok` \| `warn` \| `violated` |
| `call.ended` | `{reason: "hangup"\|"dropped"\|"instructor"}` | Конец разговора |
| `score.ready` | `{session_id}` | Оценка посчитана, можно забирать отчёт по HTTP |
| `error` | `{code, message}` | Всё, что пошло не так, — одним каналом |

`timer.tick` раз в секунду, а не на каждое изменение: таймеров штук двенадцать, а UI всё равно рисует секунды. Экономит и трафик, и работу фронта.

## События: курсант → сервер

| Событие | Payload | Смысл |
|---|---|---|
| `call.answer` | `{}` | Снял гарнитуру. Останавливает норматив «ответ ≤8 с» |
| `kio.patch` | `{fields: {...}}` | Правка карточки. Дебаунс 300 мс, шлётся только дельта |
| `dds.dispatch` | `{service: "01"\|"02"\|"03"\|"04"\|"gkh"}` | Передача в ДДС. Останавливает норматив «оповещение ≤60 с» |
| `call.hangup` | `{}` | Завершение разговора оператором |
| `callback.dial` | `{}` | Обратный дозвон после обрыва (норматив: 3 попытки по 10 с) |

**Правило: таймеры ГОСТ останавливаются событиями, а не таймаутами.** Иначе метрика времени опроса становится недоказуемой, а вся оценка у нас держится на том, что её можно предъявить методисту.

## События: сервер → наблюдателям

Пульт преподавателя и внешний монитор получают одно и то же — различается только отрисовка.

| Событие | Payload |
|---|---|
| `session.snapshot` | Полное состояние при подключении: сценарий, КИО, транскрипт, таймеры. **Обязательно** — монитор в классе включают посреди занятия |
| `transcript.append` | `{speaker: "caller"\|"operator", text, at}` |
| `kio.state` | Полная карточка целиком (не дельта — наблюдателю проще) |
| `timer.tick` | То же, что курсанту |
| `session.ended` | `{reason}` |
| `score.ready` | `{session_id}` |

Дельты курсанту, полное состояние наблюдателям — сознательно. У курсанта одно соединение и важна задержка; наблюдателей несколько, они подключаются в произвольный момент, и рассинхрон на внешнем мониторе посреди занятия дороже лишних килобайт.

## События: преподаватель → сервер (канал `control`)

Живое управление ситуацией — реализация фразы ТЗ «управление **ситуаций** с рабочего места преподавателя». Подробный разбор механики — в [STACK-BACKEND.md](STACK-BACKEND.md).

| Событие | Payload | Применение |
|---|---|---|
| `director.inject` | `{directive, mode: "next_turn"\|"immediate"}` | Директива звонящему |
| `scenario.start` | `{scenario_id, trainee, group_id}` | Запуск занятия |
| `session.stop` | `{}` | Принудительное завершение |

Восемь пресетов директив с типами применения — в [STACK-BACKEND.md](STACK-BACKEND.md). Свободный текст уходит в `directive` как есть и работает только при наличии сети: офлайн-дерево предгенерировано, и произвольную реплику в нём взять неоткуда. Кнопочные пресеты работают всегда.

**`mode: "immediate"` — только для обрыва связи.** Он рвёт TTS на полуслове тем же механизмом, что barge-in. Все остальные директивы применяются со следующей реплики: разговор не должен дёргаться от того, что преподаватель что-то нажал.

## События: станция ДДС

Оператор 112 нажал `dds.dispatch` — карточка замораживается снимком и уходит диспетчеру.

| Событие | Направление | Payload |
|---|---|---|
| `card.received` | → станции | `{card, from_operator, at}` — снимок КИО, дальше не меняется |
| `card.ack` | ← от станции | `{}` — останавливает норматив `dds_ack` (≤ 4 с) |
| `card.bounce` | ← от станции | `{missing_fields, comment}` — возврат на уточнение |
| `zone.decision` | ← от станции | `{in_zone: bool}` — норматив `zone_check` (≤ 30 с) |
| `crew.dispatched` | ← от станции | `{at}` — время выдачи приказа на выезд |
| `crew.arrived` | ← от станции | `{at}` — время прибытия |

**`card.bounce` — самая ценная механика цепочки.** Диспетчер видит, что не указан этаж, и отбивает карточку обратно. Неполнота КИО перестаёт быть абстрактным процентом в отчёте и становится сорванным выездом с конкретной причиной — ровно то, что преподаватель на занятии объясняет голосом.

Снимок карточки не меняется после передачи намеренно: оператор 112 не должен иметь возможности задним числом дописать поле, которое забыл.

## Модель КИО

Карточка информационного обмена — структура из ГОСТ Р 22.7.03-2021. **Это не наш дизайн формы, это норматив**, и на питче так и говорится.

```python
class KIO(BaseModel):
    # Служебное — заполняется системой
    card_id: UUID
    registered_at: datetime
    response_status: Literal["registered","transferred","in_progress","closed"]

    # Звонящий
    caller_number: str          # автоопределение, не редактируется
    caller_name: str | None
    caller_contact: str | None
    language: str = "ru"

    # Место
    okato: str | None
    address: str | None
    street: str | None
    building: str | None
    entrance: str | None
    floor: str | None
    coords: tuple[float, float] | None

    # Происшествие
    incident_type: str | None   # код классификатора
    description: str | None
    victims_count: int | None
    is_emergency: bool = False          # признак ЧС
    life_threat: bool = False
    evacuation_needed: bool = False

    # ДДС
    dds: Literal["01","02","03","04","gkh"] | None
    dispatch_order_at: datetime | None
    arrival_at: datetime | None
```

Плюс уточняющие поля по службе — они и показывают жюри знание предметной области:

- **01 МЧС:** характер пожара, объект, этажность, газификация
- **02 полиция:** вид правонарушения, подозреваемые, транспортное средство
- **03 медицина:** повод к вызову, способность к передвижению
- **04 прочие / ЖКХ:** тип аварии

Обязательность полей задаётся **сценарием, а не моделью**: в ложном вызове число пострадавших не требуется, в ЧС требуется. Поэтому `required_fields` живёт в YAML сценария, а полнота КИО считается против него.

## Коды таймеров ГОСТ

Одинаковые строки на бэке, фронте и в отчёте. Норматив в миллисекундах берётся из конфига, не из кода.

| Код | Операция | Норматив |
|---|---|---|
| `answer` | Ответ на звонок | ≤ 8 с |
| `interview` | **Опрос / идентификация ситуации** | **≤ 75 с** |
| `dds_notify` | Оповещение ДДС | ≤ 60 с |
| `dds_ack` | Подтверждение получения карточки | ≤ 4 с |
| `zone_check` | Проверка зоны ответственности | ≤ 30 с |
| `callback` | Обратный дозвон при обрыве | ≤ 10 с набора, 3 попытки |
| `close` | Снятие с контроля | ≤ 5 мин |

`interview` — центральная метрика демо («94 секунды при нормативе 75»), она обязана быть видна курсанту в реальном времени, преподавателю на пульте и на внешнем мониторе.

## Формат сценария

`scenarios/*.yaml`. Пишет лид, читает бэкенд, ревьюится глазами.

```yaml
id: fire-l1-kitchen
level: L1
title: "Пожар на кухне, вменяемый заявитель"
dds: "01"

caller:
  persona: adult_calm        # adult_calm | panic | aggressive | child | elderly | drunk | foreign
  voice: aidar               # голос Silero
  number: "+7 916 000-00-00"
  opening_line: "Алло! У меня на кухне горит, приезжайте скорее!"   # предгенерён в WAV

facts:                       # звонящий отдаёт ТОЛЬКО по запросу — ядро механики
  - key: address
    value: "улица Ленина, дом 14"
    reveal_on: ["адрес", "куда ехать", "где вы"]
  - key: floor
    value: "4"
    reveal_on: ["этаж", "какой этаж"]
  - key: victims
    value: "0"
    reveal_on: ["пострадавшие", "есть кто", "люди"]
    volunteered: false       # true = выдаст сам, без вопроса

ground_truth:                # эталон для детерминированной оценки
  dds: "01"
  incident_type: "fire_residential"
  required_fields: [address, floor, incident_type, victims_count, dds]
  kio:
    street: "Ленина"
    building: "14"
    floor: "4"
    victims_count: 0

events: []                   # для L3: {at: 45, type: "line_dropped"}
```

`reveal_on` — не regex, а семантические подсказки для слот-автомата: матчинг идёт по эмбеддингам, иначе «на каком этаже?» и «этаж какой» придётся перечислять вручную.

`ground_truth` отдельно от `facts` намеренно: первое — чем оценивают, второе — что знает звонящий. Смешать их — значит потерять возможность оценить оператора, который добыл факт, но записал его в карточку неверно. А это ровно та ошибка, которую тренажёр должен ловить.

## HTTP API

```
GET    /api/scenarios                      список: id, title, level, dds, status
GET    /api/scenarios/{id}                 карточка без ground_truth и facts
POST   /api/scenarios/generate             {description} → черновик сценария
PATCH  /api/scenarios/{id}                 правка черновика преподавателем
POST   /api/scenarios/{id}/publish         черновик → библиотека, только вручную

POST   /api/sessions                       {scenario_id, trainee, group_id, roles} → {session_id}
GET    /api/sessions/{id}                  состояние
GET    /api/sessions/{id}/report           отчёт: метрики, транскрипт, разбор, звенья цепочки
PATCH  /api/sessions/{id}/report           правка оценки преподавателем
GET    /api/sessions?trainee=&group=&from= история

GET    /api/groups                         учебные группы
GET    /api/groups/{id}/analytics          агрегат ошибок: системные пробелы группы

GET    /api/health                         готовность моделей — на заочке это первое, что дёрнут
```

**`group_id` в `POST /api/sessions` с первого дня.** Агрегат ошибок группы делается на второй неделе, но таблица `groups` и связь с сессией должны быть в первой миграции — иначе учебные группы придётся размечать задним числом по уже накопленным сессиям.

**`POST /api/scenarios/generate` возвращает черновик, а не публикует.** Публикует преподаватель, вручную, отдельным вызовом. Это не осторожность, а позиция: тренажёр готовит материал, методист решает.

`GET /api/scenarios/{id}` **не отдаёт `facts` и `ground_truth`** — иначе курсант откроет DevTools и прочитает адрес. Мелочь, но на демо перед методистами всплывёт именно она.

## Договорённости, которые экономят день

1. **Фронт не хранит состояние сессии.** Единственный источник истины — сервер, UI рисует то, что пришло. Пересечение правок карточки курсантом и автозаполнением из речи иначе превращается в неразрешимый спор двух состояний.
2. **`session_id` в URL, а не в сообщении.** Преподаватель открывает `/instructor?session=...`, монитор — `/wall?session=...`. Открывается со второй машины ссылкой, без логина.
3. **Ошибки — одним каналом `error`.** Никаких HTTP-кодов внутри WS.
4. **Часы — серверные.** Все `at` — серверное UTC, фронт не считает время сам. Метрика, посчитанная по часам браузера, на питче недоказуема.
