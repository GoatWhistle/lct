## Описание работы компании, актуальность задачи и описание сервиса

ГБУ «Система 112» является оператором системы-112 города Москвы, обеспечивающим функционирование единого номера экстренных служб на территории столицы. Организация отвечает за обработку вызовов и передачу информации в дежурно-диспетчерские службы (ДДС) через автоматизированные рабочие места (АРМ).

В настоящее время существует необходимость в создании специализированного программного обеспечения для подготовки операторов ДДС. Актуальность разработки обусловлена следующими факторами:

Отсутствие специализированного ПО для обучения операторов работе с реальным программным обеспечением системы-112

Потребность в систематическом обучении персонала с возможностью отработки навыков в условиях, максимально приближенных к реальным

Необходимость объективной оценки знаний и навыков операторов с использованием технологий машинного обучения

Отсутствие аналогов подобного обучающего программного обеспечения на рынке

Разрабатываемый тренажер должен представлять собой комплексное программное решение для подготовки операторов экстренных служб, включающее следующие ключевые компоненты:

Система эмуляции вызовов с использованием IP-телефонии и технологий VoIP

Модуль управления обучением с возможностью распределения заданий по уровням сложности

Компонент оценки эффективности подготовки операторов на основе анализа их действий

Интерфейс преподавателя для контроля процесса обучения

Разработка позволит:

Автоматизировать процесс обучения операторов

Повысить качество подготовки специалистов

Объективно оценивать компетенции обучаемых

Сократить время адаптации новых сотрудников

Систематизировать процесс обучения с использованием современных технологий ИИ

При разработке необходимо учесть:

Интеграцию с существующей инфраструктурой системы-112

Соответствие системным требованиям к аппаратному обеспечению

Обеспечение безопасности обрабатываемых данных

Возможность масштабирования решения под различные группы пользователей

Предназначение разрабатываемого сервиса

Сервис создается для организации комплексного обучения и повышения квалификации операторов ДДС, взаимодействующих с системой-112 города Москвы, с использованием современных технологий ИИ.

Система должна решать следующие задачи:

Обучение операторов работе с программным обеспечением системы-112

Отработка навыков обработки различных происшествий и чрезвычайных ситуаций

Контроль качества подготовки специалистов через автоматизированную оценку

Моделирование ситуаций с использованием эмуляции вызовов

Управление учебным процессом с возможностью распределения заданий по уровням сложности

Анализ эффективности обучения на основе машинного обучения

Сервис должен быть предназначен для обучения операторов различных городских служб, включая:

Специалисты ГБУ «Гормост»

Работники жилищных служб

Операторы других ДДС, взаимодействующих с системой-112

Преподаватели и инструкторы учебных центров

Руководители диспетчерских служб

Сервис должен использоваться для:

Базового обучения новых сотрудников

Периодической переподготовки действующих операторов

Аттестационных мероприятий

Контроля знаний и практических навыков

Отработки нестандартных ситуаций в безопасной среде

Мониторинга эффективности учебного процесса

Результатом использования сервиса станет:

Стандартизация процесса подготовки операторов

Повышение качества обучения персонала

Сокращение времени адаптации новых сотрудников

Объективная оценка компетенций специалистов

Создание единой системы подготовки операторов ДДС

Сервис должен обеспечивать:

Реалистичную имитацию рабочих процессов и интерфейса системы-112 без доступа к внешним сетям (локальный контур)

Автоматизированный контроль соблюдения временных нормативов и действий обучающихся, в том числе при ручном вводе информации (сравнение с эталоном)

Снижение нагрузки на преподавательский состав за счет автоматизации генерации сценариев и первичной оценки действий обучающихся

Защиту данных пользователей и учебных материалов

Масштабируемость под различные группы пользователей

Возможность удаленного контроля учебного процесса

Контролировать качество обучения через автоматизированную систему оценки (на базе ИИ)

Анализировать эффективность подготовки на основе машинного обучения

Вести учет результатов обучения и прогресса операторов

Обеспечение обучения операторов работе с эмулятором ПО системы-112

Отработка практических навыков обработки происшествий и ЧС

Контроль выполнения рабочих функций операторов (соблюдение тайминга и регламента)

Оценка уровня подготовки специалистов, в том числе на основе анализа ручного ввода текста

Формирование отчетности по результатам обучения

Управление учебным процессом с распределением заданий по уровням сложности

Сервис должен:

Реализовать эмуляцию рабочих процессов оператора 112 в локальном учебном комплексе

Обеспечить имитацию входящих вызовов (через виртуальную IP-телефонию или текстовые сообщения)

Предоставить инструменты управления обучением для преподавателя

Внедрить систему оценки действий операторов на основе нейросетевого анализа

Поддерживать работу с различными уровнями сложности заданий

Имитировать функционал и интерфейс системы-112 в изолированном контуре без доступа к внешним сетям

## Общие требования к сервису

Сервис должен обеспечивать:

Эмуляцию работы оператора системы-112 в режиме реального времени

Обработку вызовов через виртуальную IP-телефонию (VoIP)

Систему управления учебным процессом с распределением заданий

Контроль действий обучаемых операторов (тайминг, регламент)

Оценку эффективности обучения на основе машинного обучения (ИИ)

Ведение статистики по результатам обучения

Необходимо реализовать:

Многоуровневую систему аутентификации пользователей

Разграничение доступа к данным по ролям

Защиту каналов передачи данных

Резервное копирование данных с периодичностью не реже 1 раза в сутки

Система должна интегрироваться с:

Форматами данных и визуальными стандартами ГБУ «Система 112» (для обеспечения реалистичности обучения)

Локальной системой управления доступом (для администрирования учетных записей пользователей)

Локальными средствами мониторинга работоспособности (для отслеживания состояния сервера и сервисов)

## Опциональные требования к сервису

Все обязательные функции должны быть реализованы в полном объеме. Опциональные модули могут быть добавлены по желанию команды при условии сохранения изолированности контура.

Рекомендуется реализовать:

Дополнительные модули аналитики: расширенная визуализация эффективности обучения (графики, тепловые карты ошибок)

Экспорт отчетности: возможность выгрузки отчетов в стандартные форматы (Excel, PDF) для последующего использования во внешних системах

Механизм импорта обновлений: инструмент для пакетного обновления учебных материалов и сценариев (в ручном режиме)

Адаптивный веб-интерфейс: поддержка работы с мобильных устройств (в рамках локальной сети учебного центра)

Внутренний API: архитектурное решение для расширения функционала системы собственными модулями (без взаимодействия с внешними системами)

## Требования к производительности

Система должна обеспечивать (в рамках локальной сети):

Время отклика интерфейса не более 2 секунд при нагрузке до 100 пользователей

Пропускную способность не менее 20 одновременных сессий (вызовов/карточек)

Задержку при передаче голоса (VoIP) не более 150 мс

Работоспособность при кратковременных сбоях сети (до 30 секунд) с автоматическим восстановлением сессий без потери данных

Обработка данных:

Скорость записи данных в БД не менее 100 операций в секунду

Время формирования аналитических отчетов не более 30 секунд

Буферизация данных при временных сбоях для предотвращения потери информации

Масштабируемость:

Поддержка вертикального масштабирования (увеличение ресурсов сервера)

Возможность горизонтального масштабирования (добавление узлов в локальный кластер) при росте нагрузки

Минимальные требования к рабочему месту обучающегося (АРМ):

Процессор: Intel Core i5 или аналогичный

Оперативная память: от 16 ГБ

Накопитель: SSD от 256 ГБ

Сетевая карта: поддержка Gigabit Ethernet

Периферия: Гарнитура с поддержкой VoIP (программная эмуляция IP-телефона)

IP-телефон с гарнитурой и поддержкой VoIP

Минимальные требования к серверу (для работы ИИ-модуля):

Процессор: Intel Core i7 / Xeon (или аналог) от 6 ядер

Оперативная память: от 32 ГБ

Накопитель: NVMe SSD от 512 Гб

##### Роль: Администратор системы

Система должна обеспечивать администратору полный контроль над техническим состоянием и конфигурацией локального учебного комплекса. Для управления системой администратор должен иметь возможность:

Запускать и останавливать сервисы системы

Контролировать состояние всех компонентов в реальном времени

Настраивать параметры производительности системы

Выполнять обновление программного обеспечения (пакетное обновление)

Проводить резервное копирование данных

Для управления пользователями администратор должен иметь возможность:

Создавать учетные записи пользователей всех категорий

Назначать роли и права доступа

Блокировать/разблокировать учетные записи

Для управления конфигурацией системы администратор должен иметь возможность:

Настраивать параметры работы виртуальной IP-телефонии

Конфигурировать взаимодействие с локальной базой данных

Управлять настройками безопасности и политиками доступа

Настраивать параметры резервного копирования

Конфигурировать параметры журналирования (логов)

Для выполнения функций мониторинга и отчетности администратор должен иметь возможность:

Просматривать системные журналы

Анализировать статистику использования системы

Формировать отчеты об ошибках и сбоях

Отслеживать нагрузку на сервер

Контролировать показатели работоспособности системы

Для выполнения функций безопасности администратор должен иметь возможность:

Управлять политиками безопасности и правилами доступа к данным

Контролировать целостность системы

Вести аудит безопасности (логирование действий пользователей)

Система должна ограничивать администратора в:

Прямом вмешательстве в учебный процесс (администратор не может менять оценки или сценарии во время активного занятия)

Удалении критически важных данных без процедуры резервного копирования

Модификации базовых настроек безопасности без соответствующих прав

Доступе к персональным данным пользователей без необходимости (соблюдение принципа минимальных привилегий)

##### Роль: Преподаватель

Система должна обеспечивать преподавателю полный контроль над учебным процессом, включая управление ИИ-модулем и оценку действий обучающихся.

Для управления учебным процессом преподаватель должен иметь возможность:

Создавать, редактировать и валидировать (утверждать) учебные сценарии, в том числе сгенерированные нейросетью

Назначать учащимся конкретные задания и группы

Контролировать выполнение учебных задач в режиме реального времени

Отслеживать прогресс обучения и историю успеваемости

Для работы с контентом преподаватель должен иметь возможность:

Создавать новые учебные материалы и загружать дополнительные ресурсы

Классифицировать задания по уровням сложности

Редактировать и удалять неактуальные сценарии

Для оценки и анализа преподаватель должен иметь возможность:

Просматривать результаты выполнения заданий (автоматическая оценка И + экспертная оценка)

Формировать отчеты по успеваемости и статистику обучения

Получать аналитические рекомендации от системы (инсайты ИИ по типичным ошибкам группы)

Для взаимодействия с обучающимися преподаватель должен иметь возможность:

Осуществлять мониторинг выполнения заданий в реальном времени

Предоставлять обратную связь (комментарии к результатам) через интерфейс системы

Давать рекомендации по улучшению навыков

Для настройки обучения преподаватель должен иметь возможность:

Определять параметры учебных сценариев (тип происшествия, локация, сложность)

Устанавливать временные рамки (тайминг) выполнения заданий. По умолчанию значение - 30 сек.

Настраивать критерии успешности (пороги допустимых ошибок, требования к синтаксису ответов)

Система должна ограничивать преподавателя в:

Изменении системных настроек платформы (административных функций)

Удалении критически важных системных данных

Вмешательстве в работу других преподавателей

Изменении результатов обучения (оценок) без фиксации в журнале аудита

##### Роль: Обучающийся

Система должна обеспечивать обучающемуся:

Доступ к назначенным учебным материалам и сценариям

Возможность выполнения практических заданий в режиме эмуляции

Получение обратной связи (оценки) по результатам работы

Отслеживание собственного прогресса и истории ошибок

Сохранность результатов обучения в рамках локального профиля.

Для работы с учебным контентом обучающийся должен иметь возможность:

Получать доступ к списку назначенных учебных сценариев

Просматривать инструкции и методические материалы (справочную базу)

Выполнять практические задания (заполнение карточек)

Сохранять промежуточные результаты (при необходимости)

Для взаимодействия с системой обучающийся должен иметь возможность:

Принимать входящие вызовы/сообщения в режиме обучения

Использовать инструменты эмуляции работы оператора (АРМ-112)

Вводить текстовые ответы в карточку происшествия согласно учебному сценарию

Применять стандартные процедуры обработки вызовов

Для мониторинга прогресса обучающийся должен иметь возможность:

Просматривать свои результаты обучения (оценки, время реакции)

Отслеживать статистику выполнения заданий

Видеть рекомендации системы по улучшению навыков

Анализировать свои ошибки (на основе отчетов ИИ)

Для управления обучением обучающийся должен иметь возможность:

Выбирать доступные (назначенные преподавателем) учебные модули

Контролировать время выполнения заданий (таймер в интерфейсе)

Система должна ограничивать обучающегося в:

Доступе к административным и преподавательским функциям

Внесении изменений в учебные материалы и сценарии

Удалении результатов обучения

Изменении настроек системы и параметров безопасности

Доступе к учебным материалам и результатам других обучающихся

Система должна обеспечивать:

Защиту персональных данных обучающегося

Конфиденциальность результатов обучения

Надежное хранение истории обучения в локальной базе

Аутентификацию при каждом входе в систему

## Возможные пользовательские пути (сценарии)

##### Сценарий: Настройка учебной среды

Основное действующее лицо - Преподаватель. Основной рабочий процесс:

Вход участников в систему через защищенный интерфейс в локальном учебном комплексе

Выбор категории событий, настройка нейросети на генерацию конкретных типов происшествий (ДТП, пожары, медицина и пр.) в зависимости от темы занятия

Формирование «эталона» - автоматическое формирование системой эталонных ответов (сценариев), с которыми система будет сравнивать действия обучающегося

Подтверждение (частичное или полное) автоматически сформированных эталонных ответов Преподавателем

Настройка ролевой модели (параллельный процесс) - распределение прав доступа для обучающихся, чтобы в их ленту попадали только профильные события (например? Мосводоканал, Москоллектор, Управы, службы газа и пр.)

Предпросмотр - Преподаватель может ознакомиться с вопросами, генерируемыми системой, и вариантами ответов (действий) с подсветкой правильных с точки зрения системы

Коррекция (при необходимости) - в случае некорректного формирования вопроса или ответа у Преподавателя имеется контекстное поле, куда он может ввести комментарий, который должен быть отработан системой для корректировки вопроса или ответа

Обучение (при необходимости) - загрузка материалов в базу

Проверка грамматики (при необходимости) - принудительная проверка после ручных манипуляций с данными

##### Сценарий: Проведение практического занятия на АРМ-112 (карточки)

Основные действующие лица - Преподаватель, Обучающийся. Основной рабочий процесс:

Вход участниками в систему через защищенный интерфейс в локальном учебном комплексе (без доступа к внешнему интернету)

Выбор Преподавателем категории событий исходя из темы занятий (возможен множественный выбор)

Инициация Преподавателем старта обучения

Система имитирует звонок участника событий

Обучающиеся заполняют карточки событий (имитация интерфейса системы АРМ-112)

Преподаватель завершает занятие

Преподаватель формирует отчёт о практическом занятии с информацией о действиях, замечаниях (ошибках), времени заполнения карточки, отличия времени от нормативного (заданного в системе), а также грамматики.

##### Сценарий: Проведение практического занятия на АРМ-112 (действия с карточками)

Основные действующие лица - Преподаватель, Обучающийся. Основной рабочий процесс:

Вход участниками в систему через защищенный интерфейс в локальном учебном комплексе (без доступа к внешнему интернету)

Выбор Преподавателем категории событий исходя из темы занятий (возможен множественный выбор)

Выбор Преподавателем категории вопросов:

выбор сгенерированных системой карточек событий

или выбор сформированных обучающимися карточек событий

или смешанный выбор сгенерированных и сформированных карточек событий

Инициация Преподавателем старта обучения

Система формирует для обучающегося случайную карточку события

Обучающийся производит действия с карточкой события, в том числе вводит текст (например: «Сообщение принято, дежурная бригада направлена на место»). После завершения действий система выдает новую карточку события, если занятие не завершено

Преподаватель завершает занятие (в любой момент)

Преподаватель формирует отчёт о практическом занятии с информацией о действиях, замечаниях (ошибках), времени заполнения карточки, отличия времени от нормативного (заданного в системе), а также грамматики.
