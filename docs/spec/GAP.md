### Каталог карточек и утечка эталонов

До аудита `GET /api/scenarios` возвращал курсантам ЕКП, ДДС, признаки, тип и метаданные, а `GET /api/scenarios/{id}` скрывал только несколько ключей, оставляя прочие подсказки. Теперь курсант видит только `id/title/level/modes`, только карточки с режимом `self` и только сценарии базовой библиотеки либо опубликованные для преподавателя его учебной группы; сценарии без группы или чужих групп скрыты. Detail endpoint применяет те же ограничения, не раскрывает ground truth/facts/checklist и отвечает 404 для неоткрытых курсанту карточек. Instructor/admin сохраняют редакторский каталог. React не запрашивает каталог на странице материалов курсантского режима, а shared API-тип допускает role-safe сокращённый ответ. Регрессии проверяют точный набор полей каталога/detail в demo и фактическую фильтрацию чужой группы и публикацию КИО через HTTP с реальными PostgreSQL-транзакциями. Проверено: `make test-db` — **445 passed, 2 skipped, 3 deselected**; frontend `npm run typecheck` — успешно. Ограничение скрывает подсказки до выбора упражнения, но не является криптографической защитой уже выданного учебного содержания.

Backend выдаёт первую карточку сразу, остальные по расписанию, не превышая лимит ожидающих; таймер каждой начинается при фактическом поступлении. У каждой карточки независимы статусы, журнал, заметка и телефонный контекст; активная карточка сохраняется при выдаче следующей и восстановлении занятия после restart. АРМ ДДС показывает число незавершённых карточек, таймер следующего поступления и заполнение очереди; при отсутствии активной карточки возвращается в реестр. [Браузерный регрессионный smoke](../evidence/mobile-queue-regression-2026-09-23.json) подтвердил поток двух карточек с интервалом 6 с и лимитом одной ожидающей: до поступления второй первая принята, после поступления оператор переключился на вторую и вернулся, статус первой сохранился. До этого целевой checkpoint-smoke обнаружил и помог исправить потерю состояния карточки при создании следующей; повторный in-process round-trip подтвердил сохранение статуса, активной/ожидающей карточек и расписания следующей выдачи при сериализации/восстановлении снимка. Это не crash/restart с PostgreSQL. Значения темпа и лимита — настраиваемые учебные параметры, предложенные в переписке, а не окончательно подтверждённые заказчиком. Независимые нормативные таймеры при длительном ожидании и восстановление многокарточной очереди после аварийного restart ещё требуют отдельной приёмки. |

Актуализация 25.09.2026 — прежняя граница «полный браузерный прогон с живым ДДС WebSocket/статусами ещё требуется» закрыта локальной сквозной проверкой. После теста SQL подтвердил ноль временных users/groups/trainees/submissions/sessions/student scenarios, Compose project и его тома удалены.
