## Памятка по АРМ-112

Главный источник по стороне ДДС. Писалась не как учебник, а как ответ на вопросы,
которые диспетчеры задают отделу контроля, — то есть перечисляет ровно те ошибки,
на которых курсанты и будут спотыкаться. Для нас это готовая таксономия ошибок ДДС.

Нормативная база, на которую ссылается памятка (у нас в [NORMATIVES.md](NORMATIVES.md)
её не было):

- ФЗ от 30.12.2020 № 488-ФЗ — вызов экстренных служб по единому номеру «112»;
- ПП РФ от 12.11.2021 № 1931 — обязательные требования, **временные параметры**;
- ПП Москвы от 01.09.2020 № 1420-ПП и от 13.12.2022 № 2852-ПП — положение о системе-112 Москвы.

Три требования, на которых стоит работа служб:

1. Все службы МГСЧС подключены к системе-112.
2. Подключённая служба обязана обработать информацию и зарегистрировать реагирование.
3. **Диспетчер подтверждает получение карточки в течение 30 секунд** после её направления.

Ключевая механика оповещения:

```
специалист-112 выбирает формализованные признаки
        ↓
комбинация признаков → итоговый тип происшествия (по ЕКП)
        ↓
итоговому типу соответствует СПИСОК ОПОВЕЩЕНИЯ — набор служб
        ↓
каждая служба ставит свой статус реагирования
```

Оператор **не выбирает службу**. Он выбирает признаки, а список оповещения
формируется автоматически. Добавить службу вручную он может, удалить — нет.

### Статусы реагирования

Последовательный автомат, а не набор флагов: сначала доступны только «Принята»
и «Не принята», после «Принята» открываются остальные.

| Статус | Когда | Требование |
|---|---|---|
| Добавлена | автоматически при сохранении карточки | технический |
| Получена службой | автоматически при открытии карточки на АРМ | технический |
| **Принята** | реагирование будет | **в течение 30 с** |
| **Не принята** | реагирование не будет: не наша зона, не наша компетенция, дубль | **в течение 30 с, комментарий обязателен** |
| Начало реагирования | выезд сил и средств | по факту |
| Прибытие | прибытие на место | по факту |
| Проведение работ | работы начаты | по факту |
| Работы завершены | работы закончены | **закрывает карточку от правки** |
| Отказ от выполнения работ | принято, но работы не проводились | **комментарий обязателен, переводит карточку в «Отказ»** |

Отсутствие первичного статуса переводит карточку в «Не оповещено» — и она попадает
в раздел отдела контроля.

### Статусы карточки

| Статус | Значение |
|---|---|
| Зарегистрирована | сохранена в ПОВ-112 |
| Отработана | оповещение служб завершено |
| Проверена | работу специалиста-112 проверил главный специалист |
| **Не оповещено** | служба не поставила статус вовремя |
| **Отказ** | служба отказалась, карточка проверена главным специалистом |
| **Не завершено** | прошло 48 часов, нет статуса «Работы завершены» |
| Завершена | все службы отчитались |

Красные — три средних. Это и есть готовые критерии оценки для режима ДДС.

### Ошибки, которые памятка перечисляет поимённо

Прямая заготовка таксономии для второго режима занятия — каждая с реальным примером:

1. статус не проставлен вовсе;
2. статус не соответствует факту («Принята» там, где работ не будет);
3. отказ от реагирования на профильное происшествие;
4. нет комментария к «Не принята» / «Отказ»;
5. комментарий неполный — не указано, куда передана информация;
6. нет статусов хода работ, когда по происшествию идут повторные звонки;
7. нет оперативной связи с местом установки АРМ.

Правила проставления, тоже готовые критерии: соответствие факту, соответствие
компетенции, своевременность, полнота информации.

### Мелочи, которые меняют сценарии

- **Зарегистрированный адрес не всегда совпадает с местом происшествия** — заявитель
  называет адрес, где стоит сам («горит дом через дорогу»). Это механика сценария,
  а не дефект данных.
- В описании карточки лежит то, что признаками не выражается, и читать его обязательно.
- ЭРА-ГЛОНАСС в памятке — рабочий канал, а не экзотика: карточка приходит автоматически
  и **обязательно обрабатывается оператором 112**.

## Классификатор происшествий (ЕКП)

Рабочая таблица версии 046.24 с корректировкой МВД и Департамента.

| | |
|---|---|
| Листовых кодов | 1283 |
| Групп происшествий верхнего уровня | 23 |
| Колонок служб | 59 |
| Типов ЕКП-35 | 637 |

Структура строки: `Г / п1 / п2 / п3` → семизначный код → три признака → итоговый тип →
список оповещения по 59 службам.

```
1 | 1 | 5 | 7 | 1050701 | жилой дом | подъезд | открытое пламя | пожар: подъезд
```

Модификаторы меняют маршрутизацию, а не тип: **НД** — нет доступа, **УЛ** — угроза людям,
**ПП** — пострадавшие погибшие, газификация, перекрытие движения. У каждой службы своя
колонка на каждый модификатор — поэтому 59, а не 23.

**Одно происшествие оповещает 5–11 служб** в типичном случае; ровно одну — в семи
строках из 1283. Наше поле `dds` с единственным значением моделирует не ту реальность.

Группы верхнего уровня: пожары и задымления, ДТП, взрывы, угрозы взрывов, обрушения,
угрозы обрушений, стихия, экология, гидротехнические сооружения, опасные объекты,
выброс опасных веществ, транспорт, запах газа, городское хозяйство, нарушение
правопорядка, проблемы на дороге, человек в опасности, ребёнок в опасности,
смертельный исход, социальная помощь, животные, медицинская помощь, прочие.

## Билеты и задачи

32 билета по три вызова — **96 готовых учебных вызовов**, в том формате, в котором
занятие проводится сейчас, без нас. Заголовок каждого: «Отработайте вызовы от заявителя».

**Расшифровка всех 96 вызовов слово в слово — [TICKETS.md](TICKETS.md).**

Строка билета: ситуация, ФИО и телефон заявителя, адрес. Эталона нет — его знает
преподаватель, и это ровно то место, куда встаёт наша оценка.

```
БИЛЕТ 2
1  Задымление мусоропровода в жилом доме, 17 этажей, заявитель на 7-м этаже,
   открытого пламени не видит, пострадавших нет, Ким Олег Юрьевич, 916-126-34-71
   → Москва, ул. Берзарина, 21, корп. 1, под. 3, домофон 68
2  Поругался с продавцом «Мегафон», бросил трубку, 916 896 3254
   → Москва, Сущевский Вал, 5 стр. 1
3  Падение автомашины в воду, Иванова Елена Сергеевна
   → Москва, набережная Яузы, напротив Большого Нижнего пруда
```

Сложность в билетах создаётся не сюжетом, а **адресом и профильностью** — то, чего
в нашем единственном сценарии нет вовсе:

| Приём | Пример из билетов |
|---|---|
| Адрес по ориентиру | «около ст. Москва-Пассажирская Киевская, длинное помещение недалеко от участкового пункта» |
| Адрес вне Москвы | «Волгоградская обл., г. Волжский» — передача в другой регион |
| Адрес уточняется в разговоре | «ул. Станционная, 28 *(при уточнении адреса — г. Королёв, МО)*» |
| Линейный объект | «МКАД между 74 и 68 км», «съезд с МКАД, 100 метров не доезжая» |
| Непрофильный вызов | «поругался с продавцом „Мегафон“, бросил трубку» |
| Звонок очевидца, а не участника | «видит столб чёрного дыма со стороны посёлка» |
| Данные транспорта | марка, цвет, номер с пропусками: «ваз 2110 красная ? 128 ?? 177» |
| Явное «03 не требуется» | отсекает лишние службы из списка оповещения |

Билет как единица — это и есть «программа занятия», которая у нас стояла кандидатом
на отсечение. Её не надо придумывать: три вызова подряд, разные службы, разная сложность.
