# Контракт фронтенда и бэкенда

← [BACKEND.md](BACKEND.md) · [FRONTEND.md](FRONTEND.md) · Формат сценария: [../spec/SCENARIO-FORMAT.md](../spec/SCENARIO-FORMAT.md)

Единственный шов между треками. Фиксируется до кода — архитектура и фронт пишут его вдвоём и не расходятся, пока не подписан список событий и модель КИО. После этого меняется только явным уговором двоих.

**Источник истины — Pydantic-модели в `backend/app/domain/`.** `make types` гоняет их через JSON Schema в `frontend/src/shared/types/generated.ts`. Если генерация не заводится — типы пишутся руками, но тогда любая правка модели на бэке обязана прийти в PR вместе с правкой TS.

---

## Каналы

| Канал | Кто | Направление | Что несёт |
|---|---|---|---|
| `WS /ws/call/{session_id}` | курсант-оператор 112 | дуплекс, бинарь + JSON | Аудио в обе стороны, события звонка, правки КИО, подсказки |
| `WS /ws/station/{session_id}?role=dds_01` | курсант-диспетчер ДДС | дуплекс, **только JSON** | Карточка от оператора, подтверждение, отметки времени |
| `WS /ws/observe/{session_id}` | внешний монитор, пульт преподавателя | только приём, JSON | Зеркало состояния сессии без аудио |
| `WS /ws/control/{session_id}` | **только преподаватель** | только передача, JSON | Директивы звонящему, управление занятием, пометки |
| `HTTP /api/*` | все | запрос-ответ | Сценарии, сессии, история, отчёты, профиль, аналитика |

**Разделение прав — архитектурное, а не дисциплинарное.**

- У внешнего монитора нет ни аудио, ни канала записи вообще — он физически не может повлиять на занятие.
- Преподаватель смотрит через `observe` и пишет через `control`, и это **разные сокеты**. В `control` нет ни одной команды, меняющей карточку курсанта: преподаватель управляет ситуацией, а не работой обучаемого, иначе оценка перестаёт быть оценкой курсанта.
- У станции ДДС нет аудио — значит нет ни VAD, ни STT, ни TTS. Голосовой контур она не трогает.

**Сессия** создаётся с полем `mode: training | exam | self` ([../product/MODES.md](../product/MODES.md)). Режим виден всем участникам и меняет только доступность подсказок и протоколирование, но не поведение звонящего.

## Аудио по WebSocket

**Бинарные кадры, без обёртки JSON.** Направление определяется каналом.

| | Курсант → сервер | Сервер → курсант |
|---|---|---|
| Формат | PCM16 моно | PCM16 моно |
| Частота | **16 000 Гц** (требование GigaAM) | **24 000 Гц** (выход Silero v5) |
| Кадр | 20 мс = 320 сэмплов = 640 байт | чанк по предложению, переменный |

Ресемплинг в 16 кГц делает фронт в AudioWorklet — не сервер. Так с микрофона не летит 48 кГц лишнего трафика, и сервер получает ровно тот формат, который ждёт модель.

Воспроизведение TTS — **очередь `AudioBufferSourceNode`, не `<audio>`**: barge-in требует оборвать звук мгновенно, а `<audio>` так не умеет.

**Аудио-фон** ([../product/CALL-SIM.md](../product/CALL-SIM.md#аудио-фон-происшествия)) идёт отдельным JSON-событием `bg.start` — фронт крутит зацикленный файл локально, трафика фон не создаёт.

## События: сервер → курсант

| Событие | Payload | Когда |
|---|---|---|
| `call.incoming` | `{scenario_id, caller_number, level, mode}` | Занятие запущено. UI показывает входящий вызов |
| `call.started` | `{started_at}` | Курсант принял. Пошёл таймер опроса |
| `stt.partial` | `{text}` | Промежуточная расшифровка речи оператора |
| `stt.final` | `{text, at}` | Финальный чанк после endpointing |
| `caller.utterance` | `{text, at, mood}` | Реплика звонящего текстом, синхронно с аудио |
| `tts.begin` / `tts.end` | `{utterance_id}` | Рамки реплики звонящего: UI гасит индикатор «говорит» |
| `tts.cancel` | `{utterance_id, reason: "barge_in"}` | Оператор перебил. **Фронт мгновенно чистит очередь** |
| `bg.start` / `bg.stop` | `{loop, gain_db}` | Аудио-фон происшествия |
| `era.data` | `{vin, coords, passengers, impact_force}` | Автоданные ЭРА-ГЛОНАСС до соединения с водителем |
| `kio.patch` | `{fields: {...}, source: "auto"\|"operator"}` | Сервер сам распознал факт из речи либо эхо чужой правки |
| `hint.shown` | `{checklist_id, question}` | Ответ на `hint.request`: следующий неотработанный вопрос |
| `timer.tick` | `{timers: [{code, elapsed_ms, limit_ms, state}]}` | Раз в секунду. `state`: `ok` \| `warn` \| `violated` |
| `call.ended` | `{reason: "hangup"\|"dropped"\|"instructor"}` | Конец разговора |
| `score.ready` | `{session_id}` | Оценка посчитана, можно забирать отчёт по HTTP |
| `error` | `{code, message}` | Всё, что пошло не так, — одним каналом |

`timer.tick` раз в секунду, а не на каждое изменение: таймеров штук двенадцать, а UI всё равно рисует секунды.

## События: курсант → сервер

| Событие | Payload | Смысл |
|---|---|---|
| `call.answer` | `{}` | Снял гарнитуру. Останавливает норматив «ответ ≤8 с» |
| `kio.patch` | `{fields: {...}}` | Правка карточки. Дебаунс 300 мс, шлётся только дельта |
| `hint.request` | `{}` | Кнопка «Подсказка». Работает только в `training`/`self`; в `exam` сервер отвечает ошибкой |
| `self_assessment.submit` | `{missed: [checklist_id], comment}` | Самооценка **до** показа автооценки |
| `dds.dispatch` | `{service: "01"\|"02"\|"03"\|"04"\|"gkh"}` | Передача в ДДС. Останавливает норматив «оповещение ≤60 с» |
| `call.hangup` | `{}` | Завершение разговора оператором |
| `callback.dial` | `{}` | Обратный дозвон после обрыва (норматив: 3 попытки по 10 с) |

**Правило: таймеры ГОСТ останавливаются событиями, а не таймаутами.** Иначе метрика времени опроса становится недоказуемой, а вся оценка держится на том, что её можно предъявить и проверить.

## События: сервер → наблюдателям

Пульт преподавателя и внешний монитор получают одно и то же — различается только отрисовка. К перечню ниже добавляются все события курсанта, кроме бинарного аудио и частных (`stt.partial`): `transcript.append`, `kio.state`, `timer.tick`, `bg.start/stop`, `hint.shown`, `mode.set`.

| Событие | Payload |
|---|---|
| `session.snapshot` | Полное состояние при подключении: сценарий, режим, КИО, транскрипт, таймеры. **Обязательно** — монитор в классе включают посреди занятия |
| `transcript.append` | `{speaker: "caller"\|"operator", text, at}` |
| `kio.state` | Полная карточка целиком (не дельта — наблюдателю проще) |
| `timer.tick` | То же, что курсанту |
| `mode.set` | `{mode}` — баннер режима на всех экранах |
| `hint.shown` | То же, что курсанту — счётчик подсказок на пульте |
| `session.ended` | `{reason}` |
| `score.ready` | `{session_id}` |

Дельты курсанту, полное состояние наблюдателям — сознательно: у курсанта одно соединение и важна задержка; наблюдателей несколько, они подключаются в произвольный момент, и рассинхрон на внешнем мониторе посреди занятия дороже лишних килобайт.

На сокете `observe` **нет ни одного обработчика входящих сообщений**.

## События: преподаватель → сервер (канал `control`)

| Событие | Payload | Применение |
|---|---|---|
| `scenario.start` | `{scenario_id, trainee, group_id, mode}` | Запуск занятия в выбранном режиме |
| `director.inject` | `{directive, mode: "next_turn"\|"immediate"}` | Директива звонящему ([../product/CALL-SIM.md](../product/CALL-SIM.md#преподаватель-режиссёр)) |
| `reference.play` | `{}` | Автопроигрывание эталонного звонка на внешнем мониторе |
| `instructor_note.add` | `{transcript_ref, text}` | Пометка к реплике транскрипта |
| `score.override` | `{session_id, verdict, comment}` | Коррекция оценки; автооценка сохраняется |
| `scenario.publish` | `{scenario_id}` | Публикация черновика сценария в библиотеку |
| `session.stop` | `{}` | Принудительное завершение |

Свободный текст директивы работает только при наличии сети: офлайн-дерево предгенерировано, и произвольную реплику в нём взять неоткуда. Кнопочные пресеты работают всегда.

**`mode: "immediate"` — только для обрыва связи.** Он рвёт TTS на полуслове тем же механизмом, что barge-in. Все остальные директивы применяются со следующей реплики: разговор не должен дёргаться от того, что преподаватель что-то нажал.

## События: станция ДДС

Оператор 112 нажал `dds.dispatch` — карточка замораживается снимком и уходит диспетчеру.

| Событие | Направление | Payload |
|---|---|---|
| `card.received` | → станции | `{card, from_operator, at}` — снимок КИО, дальше не меняется |
| `card.ack` | ← от станции | `{}` — останавливает норматив `dds_ack` (≤ 4 с) |
| `card.bounce` | ← от станции | `{missing_fields, comment}` — возврат на уточнение |
| `zone.decision` | ← от станции | `{in_zone: bool}` — норматив `zone_check` (≤ 30 с) |
| `crew.dispatched` | ← от станции | `{at}` — время выдачи приказа на выезд |
| `crew.arrived` | ← от станции | `{at}` — время прибытия |

**`card.bounce` — самая ценная механика цепочки.** Диспетчер видит, что не указан этаж, и отбивает карточку обратно. Неполнота КИО перестаёт быть абстрактным процентом в отчёте и становится сорванным выездом с конкретной причиной — материал для разбора.

Снимок карточки не меняется после передачи намеренно: оператор 112 не должен иметь возможности задним числом дописать поле, которое забыл.

## Модель КИО

Карточка информационного обмена — структура из ГОСТ Р 22.7.03-2021 ([../spec/NORMATIVES.md](../spec/NORMATIVES.md)). Это не дизайн формы, это норматив.

```python
class KIO(BaseModel):
    # Служебное — заполняется системой
    card_id: UUID
    registered_at: datetime
    response_status: Literal["registered","transferred","in_progress","closed"]

    # Звонящий
    caller_number: str          # автоопределение, не редактируется
    caller_name: str | None
    caller_contact: str | None
    language: str = "ru"

    # Место
    okato: str | None
    address: str | None
    street: str | None
    building: str | None
    entrance: str | None
    floor: str | None
    coords: tuple[float, float] | None

    # Происшествие
    incident_type: str | None   # код классификатора
    description: str | None
    victims_count: int | None
    is_emergency: bool = False          # признак ЧС
    life_threat: bool = False
    evacuation_needed: bool = False

    # ДДС
    dds: Literal["01","02","03","04","gkh"] | None
    dispatch_order_at: datetime | None
    arrival_at: datetime | None
```

Плюс уточняющие поля по службе:

- **01 МЧС:** характер пожара, объект, этажность, газификация
- **02 полиция:** вид правонарушения, подозреваемые, транспортное средство
- **03 медицина:** повод к вызову, способность к передвижению
- **04 прочие / ЖКХ:** тип аварии

Обязательность полей задаётся **сценарием, а не моделью**: в ложном вызове число пострадавших не требуется, в ЧС требуется. Полнота КИО считается против `required_fields` сценария; у персон «ребёнок» и у ЭРА-ГЛОНАСС эталон учитывает недостижимые поля ([../product/CALL-SIM.md](../product/CALL-SIM.md#ребёнок)).

## Коды таймеров ГОСТ

Одинаковые строки на бэке, фронте и в отчёте. Норматив в миллисекундах берётся из конфига, не из кода.

| Код | Операция | Норматив |
|---|---|---|
| `answer` | Ответ на звонок | ≤ 8 с |
| `interview` | **Опрос / идентификация ситуации** | **≤ 75 с** |
| `dds_notify` | Оповещение ДДС | ≤ 60 с |
| `dds_ack` | Подтверждение получения карточки | ≤ 4 с |
| `zone_check` | Проверка зоны ответственности | ≤ 30 с |
| `callback` | Обратный дозвон при обрыве | ≤ 10 с набора, 3 попытки |
| `close` | Снятие с контроля | ≤ 5 мин |

`interview` — центральная метрика продукта: она обязана быть видна курсанту в реальном времени, преподавателю на пульте и на внешнем мониторе.

## HTTP API

```
GET    /api/scenarios                      список: id, title, level, dds, modes, topics, status
GET    /api/scenarios/{id}                 карточка без ground_truth и facts
POST   /api/scenarios/generate             {description} → черновик сценария
PATCH  /api/scenarios/{id}                 правка черновика преподавателем
POST   /api/scenarios/{id}/publish         черновик → библиотека, только вручную

POST   /api/sessions                       {scenario_id, trainee, group_id, mode, roles} → {session_id}
GET    /api/sessions/{id}                  состояние
GET    /api/sessions/{id}/report           отчёт: метрики, транскрипт, отметки, эталон, самооценка, подсказки
PATCH  /api/sessions/{id}/report           коррекция оценки преподавателем (автооценка сохраняется)
POST   /api/sessions/{id}/notes            пометка преподавателя к реплике
GET    /api/sessions?trainee=&group=&from=&mode=   история

GET    /api/trainees                       курсанты и группы
GET    /api/trainees/{id}/profile          профиль: радар, история, сильные/слабые, подсказки, пометки
GET    /api/sessions/{id}/attempts         попытки по сценарию + дельта метрик

GET    /api/groups                         учебные группы
GET    /api/groups/{id}/analytics          агрегат ошибок: системные пробелы группы

GET    /api/health                         готовность моделей
```

**`group_id` и `mode` в `POST /api/sessions` с первого дня.** Таблица `groups` и связь `trainee → group` закладываются в первой миграции, даже если пока одна группа, — размечать накопленные сессии задним числом не надо.

**`GET /api/scenarios/{id}` не отдаёт `facts` и `ground_truth`** — иначе курсант откроет DevTools и прочитает адрес. Мелочь, но на занятии перед методистами всплывёт именно она.

**Черновик сценария публикуется вручную** (`scenario.publish`): тренажёр готовит материал, методист решает.

## Договорённости, которые экономят день

1. **Фронт не хранит состояние сессии.** Единственный источник истины — сервер, UI рисует то, что пришло. Пересечение правок карточки курсантом и автозаполнением из речи иначе превращается в неразрешимый спор двух состояний.
2. **`session_id` в URL, а не в сообщении.** Преподаватель открывает `/instructor?session=...`, монитор — `/wall?session=...`. Открывается со второй машины ссылкой, без логина.
3. **Ошибки — одним каналом `error`.** Никаких HTTP-кодов внутри WS.
4. **Часы — серверные.** Все `at` — серверное UTC, фронт не считает время сам. Метрика, посчитанная по часам браузера, недоказуема.
5. **Каждое событие с подсказкой/оценкой логируется в БД.** Профиль, дельта попыток и аналитика группы строятся по журналу, а не по памяти процесса.
