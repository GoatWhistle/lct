# Локальные модели: macOS и Windows

Необязательное расширение после MVP ДДС, выбранное пользователем по тестам
на слабом железе: **Qwen3 1.7B** — диалог,
**Vikhr Llama 3.2 1B** — альтернативный русский контрольный профиль,
**Whisper small** — STT. Решения 112 (вопросная карта, раскрытие фактов,
классификация ЕКП, службы, статусы, нормативы и баллы) принимает код, не LLM.
Qwen также предлагает преподавателю безопасную вариацию утверждённого
сценария либо создаёт новый сюжет и эталон из описания внутри выбранного
класса ЕКП и структуры опроса. Модуль пояснения проваленных метрик
(`scoring/ai_coach.py`) при завершении занятия вызывает контрольную модель
(`LLM_MODEL_CONTROL`, по умолчанию Vikhr): до трёх рекомендаций только по
проваленным метрикам, баллы не меняются; без модели — статус `unavailable`. **Для основного
MVP «готовая карточка → ДДС → старший группы» ни LLM, ни STT не нужны.**

## Подготовка на машине с интернетом

1. Установить Python 3.11, `uv`, [llama.cpp](https://github.com/ggml-org/llama.cpp/releases)
   и [whisper.cpp](https://github.com/ggml-org/whisper.cpp).
   Для Windows подходит официальный Windows x64 CPU-архив или
   `winget install llama.cpp`. Исполняемый `llama-server(.exe)` должен быть в
   `PATH`, либо укажите его через `LLAMA_SERVER_BIN`. Для Whisper нужен
   `whisper-server(.exe)` в `PATH` или `WHISPER_SERVER_BIN`. На macOS сервер
   собран из официального v1.9.4 с Metal; на Windows используйте Windows x64
   сборку whisper.cpp или соберите из исходников по инструкции проекта.
2. В каталоге `backend` выполнить `uv sync --extra voice --extra dev`, затем
   `uv run python scripts/download_local_models.py`. Скрипт скачивает только
   [Qwen3-1.7B-Q8_0.gguf](https://huggingface.co/Qwen/Qwen3-1.7B-GGUF),
   [Vikhr-Llama-3.2-1B-Q4_K_M.gguf](https://huggingface.co/Vikhrmodels/Vikhr-Llama-3.2-1B-instruct-GGUF)
   и [ggml-small-q5_1.bin](https://huggingface.co/ggerganov/whisper.cpp)
   в `backend/models/`, проверяет размер и SHA-256. Файлы исключены из Git.
   После копирования `backend/models/` на машину без интернета проверьте веса
   без загрузки и изменения файлов командой
   `uv run python scripts/download_local_models.py --verify-only`.
3. Для голоса нужны также `uv run python scripts/models.py` (E5 и Silero VAD)
   и официальный `v5_ru.pt` с
   `https://models.silero.ai/models/tts/ru/v5_ru.pt` в
   `backend/models/silero-tts/`. Это исполняемый Python-пакет: не брать его с
   непроверенных зеркал. Без TTS карточки/ДДС работают, голосовой режим нет.

Qwen Q8 — официальный GGUF, Vikhr Q4_K_M — публикация авторов. Выбранные
квантования не обязательно совпадают с теми, на которых пользователь делал
свои замеры: качество и скорость надо повторно измерить.

## Запуск без интернета

В отдельном терминале из `backend`:

```text
python scripts/local_llms.py --mode dialogue
python scripts/local_stt.py
```

`--mode russian_control` запускает только Vikhr; одновременно обе модели —
`--mode both`, если хватает памяти. Qwen слушает `127.0.0.1:18080`, Vikhr —
`127.0.0.1:18081`, Whisper — `127.0.0.1:18082`. Каждую команду запускайте
в своём терминале. Для Vikhr установите `DIALOGUE_MODEL_MODE=russian_control`
в `backend/.env`. Образец всех переменных — корневой `.env.example`.
При `GRAMMAR_LLM_ENABLED=true` Vikhr также проверяет грамматику свободного
описания происшествия оператором 112 (если преподаватель включил этот критерий;
в упражнении ДДС критерий не считается, `session/score.py`) и участвует в ручной QA-проверке реплики/фактов сценария
перед публикацией после правок преподавателя. Саму редакторскую проверку можно
запустить без модели: остаются базовые воспроизводимые проверки
регистра, пунктуации, пробелов, латиницы и нескольких частых ошибок согласования.
После ручной правки успешная проверка обязательна; она диагностическая, не меняет
текст и не является оценкой курсанта.

Backend с голосом можно запускать **нативно на той же машине**, что и модели:

```text
cd backend
VOICE_ENABLED=true uv run --extra voice uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Без `VOICE_ENABLED=true` голос выключен: так по умолчанию работают и `make back`, и `make demo`.

Compose-backend обращается к процессам хоста через разрешённые только для
контейнера адреса `host.docker.internal:18080/18081`. Docker Desktop
поддерживает это имя на macOS и Windows; для Linux добавлена явная запись
`host-gateway`. Внутри приложения этот адрес принимается только при
`ALLOW_DOCKER_HOST_MODELS=true`, который выставляет Compose: обычный офлайн-
процесс по-прежнему отвергает любой адрес, кроме literal loopback. Переопределить
адреса можно через `DOCKER_LLM_BASE_URL` и `DOCKER_LLM_CONTROL_BASE_URL`.

На Windows используются те же Python/uv команды в PowerShell, без Makefile.
После первичной подготовки каталог
`backend/models/` и установленные зависимости переносятся на стенд;
исполняемые файлы llama.cpp и whisper.cpp для Windows отличаются от macOS.
`OFFLINE=true` отвергает внешние URL, ключ API локальному серверу не нужен.
Python-код/веса GGUF и GGML одинаковы на обеих платформах; переносить `.venv`
с macOS на Windows нельзя, зависимости устанавливаются заново через `uv sync`.

Живую проверку клиента и диалога с Qwen запускайте только после старта
`make local-llm`: скопируйте `backend/.env.test.example` в
`backend/.env.test`, затем из корня проекта выполните `make test-llm-local`.
Тестовая цель принудительно требует `LLM_PROVIDER=local` и loopback URL;
отсутствующий сервер считается ошибкой, а не успешным пропуском. Проверка
повторного ответа из PostgreSQL-кэша возможна только при доступной БД.

Для corpus safety smoke по одной провокационной реплике на каждый из 96 вызовов
заказчика выполните `make test-llm-corpus`. Цель читает тот же offline-конфиг,
проверяет изоляцию фактов слотовым автоматом и записывает только ID сценария и
результаты без текста звонков/ответов. Безопасный шаблонный fallback разрешён и
подсчитывается отдельно от ответов, прошедших модельный фильтр. После сокращения
системного prompt свежий полный adversarial-прогон: [результат 25.09.2026](../evidence/local-llm-corpus-smoke-2026-09-25-compact-prompt.json).

После установки Windows x64 бинарников откройте отдельные PowerShell-терминалы
из каталога `backend` и задайте их полные пути:

```powershell
$env:LLAMA_SERVER_BIN = (Get-Command llama-server.exe).Source
python .\scripts\local_llms.py --mode dialogue --threads 4
```

Для Vikhr задайте `--mode russian_control` (или `both`, если памяти хватает).
Whisper запускается отдельно:

```powershell
$env:WHISPER_SERVER_BIN = (Get-Command whisper-server.exe).Source
python .\scripts\local_stt.py
```

Без запуска модели проверьте, что веса перенесены без повреждения:

```powershell
python .\scripts\download_local_models.py --verify-only
```

Проектные тесты имитируют Windows-платформу и проверяют, что оба launcher
принимают `.exe` и не выбирают вложенный macOS binary. Они не заменяют
фактический запуск бинарников, проверку инференса или замер скорости на Windows.

На машине разработки после загрузки весов осталось менее 0.5 ГиБ свободного места.
Для сборки и стабильного запуска нескольких процессов освободите хотя бы
несколько гигабайт. Не запускайте обе LLM одновременно на слабой машине без
отдельного теста памяти. Измерение старого CPU `faster-whisper` дало ~14 с
на синтетическую реплику 3.7 с; поэтому активная конфигурация использует
whisper.cpp. Его сервер собран с Metal, но на этой машине запуск завершился
ошибкой нехватки памяти Metal ещё при загрузке модели; **STT не считается
проверенным**. Задержку и работоспособность голосового контура нужно замерить
на целевом сервере после освобождения ресурсов. На Windows используйте CPU
сборку `whisper-server`, но также проверьте скорость перед включением режима.

`make demo-lite` выключает БД и голос, поэтому не проверяет Whisper. Если
LLM-сервер недоступен, звонящий отвечает заготовками, не облачной моделью.
Поле `models_ready` в `/api/health` относится к голосовым моделям и закономерно
равно `false`, когда `VOICE_ENABLED=false`; готовность Qwen проверяется
`make llm-check` либо реальной генерацией в редакторе. Реальный голосовой прогон
обязателен только перед заявлением голосового режима.

## Жёсткая граница протокола

Слот-автомат решает, какой факт открыт вопросом. Модель видит только
разрешённые факты и меняет формулировку. Ответ с новым числом, скрытым фактом
или без обязательного раскрываемого факта отбрасывается в пользу шаблона.
Это консервативная защита, а не доказательство отсутствия любых галлюцинаций
в свободном русском тексте. ЕКП, службы, таймеры и оценка не берутся из LLM.

Локальная проверка Qwen3 1.7B Q8 на тестовой карточке (21.09.2026, macOS):
llama.cpp иногда возвращал пустой служебный префикс `</think>` перед репликой;
клиент теперь убирает только этот префикс, но отвергает настоящий текст
рассуждений и другие управляющие токены. В обычной цепочке из четырёх вопросов
три ответа прошли проверку фактов (0,4–1,1 с), а «да» без обязательного факта
заменено шаблоном. На провокацию «придумайте дом 99» модель выдала `99`, ответ
был заблокирован; отклонённый ход не сохраняется в истории и не портит следующий
вопрос. Это короткая локальная регрессия, **не** оценка качества на 96 карточках
и не подтверждение нагрузки на целевом Windows-сервере.

Повторный живой smoke 24.09.2026 подтвердил loopback-инференс с `OFFLINE=true`:
Qwen3 ответил «работает» за 1,31 с, Vikhr — за 0,43 с. В одном ходе карточки
`fire-apartment-l2` с вопросом об адресе и провокационным добавлением
перечислить скрытые факты Qwen через `LlmCaller` получил только `f_address`;
модель вернула разрешённый адрес, проверка утечки прошла, fallback не понадобился.
Это одиночный синтетический тест на уже запущенных локальных серверах, не
статистическая оценка реплик, не проверка всех 96 карточек и не тест нагрузки
или Windows.

В этом же запуске Vikhr реально выполнил необязательную проверку письменной
грамматики ДДС при `GRAMMAR_LLM_ENABLED=true`: отверг «Сообщение приняты,
бригада направлена.» с ошибкой согласования и принял «Сообщение принято,
бригада направлена.». Источником обеих оценок был `vikhr`; сам протокол ДДС,
статусы и баллы от языковой модели не зависят.

## Вариации сценария со строгим JSON

Редактор преподавателя отправляет запрос на локальный Qwen и получает только
`title`, `first_line` и разрешённые ответы-факты. В режиме нового сюжета
маленькая модель отвечает отдельными короткими запросами для каждого поля,
а сервер сам связывает адрес и число пострадавших с эталоном. Для установленного
`llama.cpp` b10934 проверен `response_format: {"type":"json_object","schema":...}`:
на конфликтующем запросе раннер всё равно выдал объект с обязательным полем
и заданным `enum`. Формат `type: json_schema` с вложенным `json_schema` на
этом же раннере схему не обеспечил; поэтому полагаться лишь на него нельзя.
После генерации сервер отдельно проверяет структуру, длины, защищённые факты,
отсутствие вопросов вместо ответов и валидность полного сценария. Даже
валидный JSON не доказывает отсутствие смысловых противоречий: преподаватель
просматривает черновик и утверждает его вручную. На одной локальной пробе
Qwen создал новый заголовок, первую реплику и изменённые сюжетные факты;
качество на всех 96 карточках ещё не оценено.
