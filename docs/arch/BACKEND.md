## Голосовой контур

**Дополнительный режим P2, по умолчанию выключен (`VOICE_ENABLED=false`).** Основной путь — упражнение ДДС на готовой карточке и упражнение 112 по текстовой вводной; им голос не нужен ([../product/OVERVIEW.md](../product/OVERVIEW.md)). Раньше контур был критическим путём проекта — ниже описано, как он устроен.

### Модели

STT по умолчанию — Whisper small через локальный `whisper-server` (`STT_MODEL=whisper-small`, `make local-stt`). GigaAM v3 RNNT через `onnx-asr` остался запасным (`STT_MODEL=gigaam-v3-rnnt`, веса — `scripts/models.py --legacy-gigaam`); замеры в [../LATENCY.md](../LATENCY.md) сделаны на нём. TTS — Silero v5, VAD — Silero VAD. Задержку Whisper на целевой машине ещё предстоит замерить ([LOCAL-MODELS.md](LOCAL-MODELS.md)).

### Пайплайн

Без фреймворков ([STACK.md](STACK.md)).

```
mic_frames → [VAD] → utterance → [STT] → text → [звонящий] → sentences → [TTS] → pcm_chunks
```

VAD работает на входящих кадрах, законченные фразы идут в `asyncio.Queue`, ответ на каждую — одна задача: распознавание, реплика звонящего, синтез и ожидание конца воспроизведения. Barge-in — отмена этой задачи: гаснут и LLM-запрос, и синтез, и воспроизведение одним движением.

**Три техники, дающие почти всю ощущаемую скорость:**

1. **Синтез по предложениям** — ответ режется на предложения (`text.py`), звук стартует с первого. LLM-клиент сейчас без стриминга: реплика приходит целиком.
2. **Chunked TTS** — Silero по замеру синтезирует в ~10 раз быстрее реального времени ([../LATENCY.md](../LATENCY.md)), синтез обгоняет воспроизведение, очередь чанков не пустеет.
3. **Предгенерация первой реплики** — «Алло! Помогите!» лежит готовым WAV и играет мгновенно.

Плюс **филлеры**: при задержке >1 с играть «алло?..», «вы там?..». Маскирует паузу и сюжетно оправдано для паникующего — не костыль, а поведение персонажа.

### Endpointing и barge-in

**600 мс — рабочая рекомендация, не подбирать заново.** Ниже 400 мс режет на паузах внутри фразы («улица... эээ... Ленина»), выше 800 мс ощущается как тормоз. Операторы говорят с паузами, ложное срабатывание хуже задержки.

**Barge-in обязателен** — оператор перебивает звонящего, это ключевой навык диспетчера. Цель — под 150 мс. Схема двухслойная: фронт по локальному энергетическому гейту гасит звук мгновенно, сервер по VAD подтверждает и шлёт `tts.cancel`, отменяя LLM и TTS. Сервер — авторитет, фронт — скорость.

Гарнитура снимает проблему эхо-компенсации: микрофон не слышит собственный динамик.

### Деградация

Фиксируется заранее, решение принимается сразу, как появился сигнал:

| Сигнал | Шаг |
|---|---|
| Whisper small не укладывается в бюджет | GigaAM v3 RNNT (`STT_MODEL=gigaam-v3-rnnt`); CTC по скорости не выигрывает ([../LATENCY.md](../LATENCY.md)) |
| STT не годится совсем | Текстовые упражнения 112 и ДДС — основной путь, голос не нужен |
| LLM недоступна | Таблица реплик (`tree.py`) или заготовки — плановый режим, а не костыль |

## Звонящий

Владелец механики — AI-инженер. До сборки голосового контура живёт в `make repl`: текстовый диалог со звонящим без голоса.

### Слоты

**Звонящий не выдаёт информацию сам** ([../product/CALL-SIM.md](../product/CALL-SIM.md)). Реализация — детерминированный `slots.py`: слот-автомат сопоставляет реплику пункту чек-листа по локальным эмбеддингам, хранит открытые факты и **подмешивает модели только разрешённые**. Поля/условия `hidden` и `approach`, требовавшие бы LLM-суждения о действии курсанта, схемой сценария отвергаются.

- вопрос сопоставляется чек-листу локальными эмбеддингами, без LLM-классификации;
- **повторный вопрос по раскрытому факту** помечается и передаётся в `persona.py` как раздражение.

Побочная польза: тот же автомат детерминированно отвечает на вопрос «спросил ли оператор про этаж» — без этого оценка полноты опроса становится догадкой LLM.

### Персоны и дуга

`persona.py`: базовые профили + `evasive`/`child`/`foreigner`; эмоциональная дуга по этапам приёма вызова; состояние меняют директивы и повторы. 70% восприятия эмоции — текст (обрывки, повторы, незаконченные предложения); просодия SSML задумывалась добавкой, в коде не используется.

### Офлайн — `tree.py`

Таблица реплик строится `scripts/pregenerate.py` (`make pregen`). Это не граф диалога: ветвление делает слот-автомат, а таблица индексируется парой «событие × настроение» — дуга и директивы переключают настроение, а не текст. На занятии без сети — локальный матчинг эмбеддингами, ~300 мс. Проверяется с физически выключенной сетью, не «в теории».

Это архитектура воспроизводимого тренажёра: сценарий занятия должен быть проверен до занятия и звучать одинаково у каждой группы.

Кэш всех ответов LLM по хешу контекста — в Postgres; ускоряет повторы и служит накопителем материала для таблицы. Модель только локальная: в офлайне нелокальный URL отвергается.

## Оценка

### Правила и воспроизводимые метрики

Процедурные действия, сроки, поля КИО, маршрутизация, решения и статусы оцениваются кодом по эталонам сценария и нормативам. LLM-судьи нет, распределения итогового балла «60% правила / 40% LLM» нет; веса метрик и лимиты таймеров настраивает преподаватель (`weights.py`, `LessonCriteria`). `ai_coach.py` при завершении занятия просит контрольную модель (по умолчанию Vikhr) пояснить проваленные метрики; ответ ограничен ключами этих метрик и баллы не меняет. Единственное опциональное участие модели в критерии — Vikhr для языковой проверки описания в упражнении 112, если преподаватель включил критерий грамматики и администратор включил `GRAMMAR_LLM_ENABLED`; результат имеет объяснимый E4 finding. Базовая локальная проверка работает и без модели. LLM не решает, какой факт открыть, как классифицировать происшествие, какую службу выбрать, какой статус принять или какой балл назначить.

Метрики, считаемые кодом:

- нормативы ГОСТ Р 22.7.03-2021 (опрос ≤ 75 с и остальные таймеры);
- полнота чек-листа: добытые факты против обязательных;
- корректность типа происшествия и ДДС против `ground_truth`;
- точность адреса и числа пострадавших;
- полнота обязательных полей КИО;
- обратный дозвон при обрыве;
- ДДС: решение по карточке за 30 с, выбор бригады, статусы и комментарии, ошибки D1–D6 (`dispatcher.py`).

### Таксономия и компетенции

`taxonomy.py` размечает каждую метрику и отметку в транскрипте кодом E1–E6 (для ДДС — D1–D6, `dispatcher.py`) с обоснованием ([../product/METHODOLOGY.md](../product/METHODOLOGY.md)). `competency.py` группирует метрики в радар из шести компетенций — это чистая проекция, без пересчёта весов: радар и оценки всегда согласованы.

### Разбор — `report.py`

Собирает отчёт сессии: транскрипт с отметками (код + обоснование), эталонные вопросы по шагам, пропущенные пункты чек-листа, самооценка и её расхождение с автооценкой, использованные подсказки, пометки преподавателя, радар. Ни одной отметки без объяснения.

## Сессии, библиотека, данные

### Состояние сессии

`state.py` держит КИО, транскрипт, таймеры, режим и попытку; `hub.py` — реестр сессий и подписки наблюдателей. **Один воркер uvicorn на узел, и это принципиально:** состояние живой сессии в памяти процесса, два воркера — и преподаватель подключится к другому процессу, чем курсант. Каждое действие курсанта или преподавателя — одна `hub.operation`: на выходе один `SessionStore.commit` пишет в одной транзакции проверку `(node_id, epoch)`, append-only строки (реплики, подсказки, заметки, самооценку, оценку с аудитом) и снимок, а события уходят подписчикам только после него; сбой commit отбрасывает события и закрывает занятие на узле. Без БД (`DEMO_NO_DB`) и в юнит-тестах работает in-memory adapter. `checkpoint.py` сериализует этот снимок: снимок — `model_dump` сохраняемой части сессии (`PersistedSession`), живые объекты (голос, звонящий, запись) в него не входят и пересобираются при загрузке; снимок другой версии не читается. Для двух узлов есть opt-in кластер (`docker-compose.cluster.yml`: Nginx affinity по UUID сессии, lease/fencing в PostgreSQL) — [SCALE-OUT.md](SCALE-OUT.md).

Подсказка (`hint.request` в `api/ws/call.py`) отдаёт следующий неотработанный вопрос чек-листа по запросу курсанта — детерминированно, без LLM; в режиме `exam` запрос отклоняется.

### Наблюдатели

`observe.py` — вещание наблюдателям. Два требования:

1. **`session.snapshot` при подключении.** Внешний монитор в классе включают посреди занятия — он обязан показать текущее состояние, а не ждать следующего события.
2. **На сокете `observe` нет ни одного обработчика входящих сообщений.** Внешний монитор физически не может повлиять на занятие; преподаватель пишет через отдельный `control`.

### Сценарии

`loader.py` валидирует **все** YAML на старте и падает с внятным сообщением, если хоть один битый. Сценарии пишет методист, не программист; сломанный YAML, найденный посреди занятия, — сценарий, которого не должно случиться.

`generation.py`: локальный Qwen пишет только сюжетные поля вариации или нового сюжета в строгом JSON ([LOCAL-MODELS.md](LOCAL-MODELS.md#вариации-сценария-со-строгим-json)); адрес, пострадавшие, классификация, список оповещения и протокол оценки ему недоступны. Эталон не генерируется, а выводится из фактов кодом — иначе модель напишет в фактах «Ленина, 14», а в эталоне «Ленина, 4». Сервер проверяет результат, черновик публикуется преподавателем вручную. `editor.py` — копия утверждённого шаблона без ИИ.

### БД

PostgreSQL 16: сценарии, сессии, реплики, отметки, самооценки, подсказки, попытки, заметки, оценки, курсанты, группы, кэш LLM.

**Таблица `groups` и связь `trainee → group` — в первой миграции, даже пустыми.** Агрегат ошибок группы делается позже, но размечать учебные группы задним числом по накопленным сессиям — лишняя работа и лишняя миграция.

История сессий с фильтром по курсанту, режиму и датам — преподавателю нужно видеть прогресс группы и самостоятельную работу курсантов.

## Команды

```
make dev          docker compose up: postgres + backend --reload + frontend
make back         бэкенд нативно, без голоса по умолчанию
make models       эмбеддинги e5 и Silero VAD в backend/models/; Silero TTS — вручную
make local-models Qwen3 1.7B, Vikhr 1B, Whisper small с проверкой SHA-256
make local-llm    llama.cpp на loopback (mode=dialogue|russian_control|both)
make local-stt    whisper.cpp server на loopback
make seed         залить сценарии из /scenarios в БД
make types        domain/events.py → frontend/src/shared/types/generated.ts
make repl         текстовый диалог со звонящим без голоса
make pregen       таблица реплик звонящего для офлайна
make demo         основной стенд ДДС: база, карточки, бэкенд, фронт (VOICE_ENABLED=true — с голосом)
make demo-lite    демонстрация без Docker, БД и голоса
```

`make demo` пишется заранее, а не в последний день — команда, которой поднимают стенд, должна обкатать её десяток раз.
