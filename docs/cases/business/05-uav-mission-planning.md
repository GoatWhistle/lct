## ТЗ

### Актуальность

Одним из важнейших применений беспилотных воздушных судов (БВС) как на сегодняшний день, так и в ближайшем будущем, является мониторинг объектов и территорий с воздуха. Ценность материалов воздушной съёмки зачастую определяется оперативностью их получения. Полёты БВС выполняются в автономном режиме.

### Описание задачи

Расчёт **оптимального полётного задания для группы БВС**.

Критериев оптимальности может быть два: либо **минимальное время** выполнения задания, либо **минимальный износ техники** (по сумме лётных часов).

Исходными данными являются:

1. Координаты доступных **взлётно-посадочных пунктов**
2. Перечень доступных **БВС**
3. Координаты **области**, в которой необходимо провести съёмку
4. **Виды съёмки** (фото видимого диапазона, мультиспектр, ИК, лазерное сканирование, геовизическая съёмка)

### Ресурсы от организатора

- Характеристики линейки БВС
- Характеристики камер, используемых в качестве полезной нагрузки БВС

## Что даёт организатор и что это значит

**Дают:** характеристики линейки БВС и характеристики камер (полезной нагрузки). Это **параметры для расчёта**, а не датасет. Критерий срабатывает: задача оптимизационная, обучать нечего, GPU не нужен.

Именно из этих характеристик строится вся расчётная цепочка (GSD → высота → ширина захвата → перекрытие → время), поэтому данные организатора — не иллюстрация, а прямой вход модели.

**Чего у Planner (и большинства планировщиков) нет — оптимального распределения работ между РАЗНОРОДНОЙ группой дронов с разных точек по двум критериям.** Вот куда бить. ТЗ прямо про это: «группа БВС», «перечень доступных БВС» (разные модели), «координаты доступных взлётно-посадочных пунктов» (несколько точек).

**Практический вывод:** нельзя игнорировать физику полёта. Планировщик, не учитывающий автономность и перекрытие снимков, для Геоскана — игрушка. Реализм ограничений важнее красоты интерфейса. Руководитель разработки будет смотреть не «нарисовали ли галсы», а «как распределили и по какому критерию».

Направление «Образование» у второго эксперта — возможно, кейс имеет и обучающую ценность для них.

## Как решать

### Что это за задача формально

Комбинация двух классических задач:

**1. Coverage Path Planning (CPP)** — как облететь площадь, покрыв её камерой заданного типа. Классика в аэрофотосъёмке:
- область разбивается на полосы (boustrophedon / «змейка»)
- ширина полосы = ширина захвата камеры с учётом высоты и перекрытия (обычно 60–80% продольное, 30–60% поперечное)
- маршрут внутри области — покрытие галсами

**2. Multi-UAV Task Allocation + Routing** — распределение области между несколькими БВС с разных взлётных точек: какой дрон летит в какую часть области, с какого пункта, с учётом дальности/времени полёта (батарея).

**Ключевое отличие от Б№3 (наземные маршруты):** здесь нет дорожной сети — расстояния евклидовы (полёт по прямой), но есть жёсткое ограничение **дальности/времени автономного полёта**, необходимость возврата на посадку и **привязка типа съёмки к возможностям камеры конкретного БВС**.

### Расчётная цепочка съёмки (детерминированная, из характеристик)

```text
Требуемое разрешение (GSD, см/пиксель)
   → высота полёта H = GSD × f / (пиксель сенсора)   [f — фокусное]
   → ширина захвата на земле W = H × (ширина сенсора / f)
   → шаг между галсами = W × (1 − поперечное перекрытие)
   → шаг съёмки вдоль галса = высота кадра × (1 − продольное перекрытие)
   → скорость × время = длина всех галсов
```

**Перекрытие — обязательно:** продольное 60–80%, поперечное 30–60%. Без него фотограмметрия не сшивает модель. **Геоскан это проверит первым** — если галсы вплотную без перекрытия, решение нерабочее.

Эта цепочка — не «примерно так полетим», а обоснованный расчёт, который оценит инженер Геоскана.

### Автономность — жёсткое ограничение

Каждый БВС имеет предельное время/дальность полёта (батарея или топливо). Из характеристик:

```text
доступное время полёта T_max
   → за вычетом взлёта/посадки/возврата на базу T_eff
   → максимальная длина маршрута L_max = скорость × T_eff
```

Если участок длиннее L_max → **несколько вылетов** (возврат, смена батареи, продолжение) либо передача другому дрону. Это ядро реализма: площадь большого поля не покрывается за один вылет.

### Разные БВС — разные параметры

«Перечень доступных БВС» = флот из разных моделей. У каждого свои: скорость, автономность, набор камер, потолок. **Крыло** (самолётного типа) — быстрое, большая площадь, но не висит; **мультиротор** — медленнее, но точнее и универсальнее по нагрузке. Модель должна это различать.

### Два критерия оптимальности — разобрать до конца

ТЗ даёт ровно два, и они дают принципиально разные решения. Это не «слайдер для красоты», а два разных режима планирования.

**Режим «минимальное время» = минимизация makespan.** Вся съёмка должна закончиться как можно раньше:
- максимальная параллельность: все годные дроны в воздухе одновременно
- балансировка участков так, чтобы дроны заканчивали примерно вместе (иначе время определяется последним)
- быстрые дроны (крыло) берут большие площади

Формально: `min (max_i (время завершения дрона i))`. Классический makespan minimization — как в планировании задач на параллельных машинах.

**Режим «минимальный износ» = минимизация суммы лётных часов.** Беречь технику:
- задействовать **минимум** дронов (каждый лишний вылет = износ)
- каждый дрон летит по максимально плотному маршруту без лишних перегонов
- допустимо, что съёмка идёт дольше — один дрон делает несколько вылетов

Формально: `min (Σ_i лётное_время_i)`. Ближе к классическому VRP.

**Почему они конфликтуют — конкретный пример на защиту.** Поле, 3 дрона в наличии:
- **Мин. время:** все 3 летают параллельно, каждый ~1/3 поля, съёмка за 40 минут, суммарно 120 минут лётного ресурса
- **Мин. износ:** 1 дрон делает 3 вылета, съёмка за 130 минут, но суммарно 105 минут (нет перегонов между разнесёнными участками, оптимальная упаковка)

Показать оба на одной карте с числами — прямое исполнение ТЗ и демонстрация, что за критериями стоит настоящая разница, а не переименованная одна модель.

### Привязка съёмки к камере — ограничение, которое легко упустить

Пять типов съёмки: фото видимого диапазона, мультиспектр, ИК, лазерное сканирование (LiDAR), геовизическая (вероятно, геофизическая — магнитометрия/гравиметрия). Каждый требует своей полезной нагрузки. LiDAR тяжёлый — не всякий дрон поднимет. Мультиспектр и ИК — специальные камеры. Значит:

- **не каждый БВС может выполнить любой тип съёмки** — нужна матрица «тип съёмки → БВС с подходящей камерой»
- если задание требует нескольких типов над одной областью — возможно, нужны **несколько пролётов разными дронами** (или один дрон с несколькими нагрузками, если характеристики позволяют)
- разные типы съёмки требуют разной высоты/перекрытия/скорости → **разные параметры галсов для одной и той же области**

Это превращает задачу из «поделить площадь» в «поделить площадь × типы съёмки с учётом того, кто что может». Аналог квалификации инженера в Б№3, но с дополнительным измерением — тип съёмки диктует ещё и параметры полёта.

**Ход для защиты:** показать, что при запросе «этот участок — мультиспектр, тот — LiDAR» система назначает дронов по наличию нагрузки, а не абы как. Немногие дойдут до этого уровня.

### Coverage Path Planning — как не утонуть в геометрии

Покрытие площади галсами — решённая задача, но невыпуклые области с дырами (запретные зоны, водоёмы) усложняют.

**Стратегия по возрастанию сложности:**
1. **Выпуклый полигон** — простая «змейка» (boustrophedon) под оптимальным углом (вдоль длинной стороны — меньше разворотов). Реализуется за час на Shapely
2. **Невыпуклый** — трапецоидальная/boustrophedon-декомпозиция на выпуклые ячейки, покрытие каждой, соединение. Есть готовые реализации
3. **С дырами (запретные зоны)** — вычесть дыры из полигона перед декомпозицией

**Рекомендация:** начать с (1), довести до конца, потом (2). Оптимальный угол галсов — дешёвая оптимизация с заметным эффектом (меньше разворотов = меньше времени и износа). Развороты стоит учесть — на крыле разворот дорогой (большой радиус), это влияет на выбор направления галсов.

**Что НЕ делать:** не уходить в 3D-облёт рельефа, обход препятствий по высоте, ветровую модель — если только не осталось времени. Плоская модель покрытия + автономность + аллокация закрывают суть.

### Декомпозиция + аллокация — центральный алгоритм

Сердце многодроновой части.

**Наивно (плохо):** разрезать площадь на N равных кусков по числу дронов. Игнорирует разные скорости, автономность, расположение баз.

**Правильно:** делить **пропорционально производительности** дрона (скорость × автономность × ширина захвата) и с учётом близости к его базе, чтобы минимизировать перегон база→участок.

**Подход, реалистичный за хакатон:**
1. Оценить «стоимость» покрытия каждой единицы площади каждым дроном (с его базы, его камерой)
2. Задача назначения участков дронам — через OR-Tools или жадно + локальное улучшение
3. Пересчёт под выбранный критерий (makespan vs сумма)

Полноценный VRP тут избыточен — область непрерывна, а не набор точек. Гибрид «декомпозиция площади + назначение кусков» проще и адекватнее.

### Порядок работы

1. **Час 1–2:** покрытие выпуклого полигона галсами на Shapely + расчёт параметров из характеристик. Проверить на одном дроне, одном типе съёмки
2. **Часы 3–6:** автономность (несколько вылетов), привязка камеры, декомпозиция на несколько дронов
3. **Параллельно:** карта на MapLibre, отрисовка галсов и маршрутов
4. **Далее — ядро ценности:** два режима оптимальности с реальной разницей
5. **В конце:** невыпуклые области, сравнение режимов, полировка демо

**Принцип:** одиночное покрытие — фундамент (его умеет и Geoscan Planner), выигрыш — в многодроновой оптимизации по двум критериям. Не застрять на красоте галсов, дойти до аллокации.

## Где выигрывается / что даёт отрыв

**1. Два режима оптимальности — прямо из ТЗ.** Показать оба и разницу между ними: «быстро» = все дроны в воздухе параллельно, «бережно» = меньше дронов, меньше лётных часов, дольше по времени. Переключатель с визуализацией разницы в цифрах.

**2. Ограничение автономности — сердце реализма.** Учёт дальности, времени возврата на посадку, необходимости нескольких вылетов при большой площади — то, что отличает рабочий планировщик от «нарисовали галсы». Геоскан это знает профессионально.

**3. Привязка съёмки к камере.** Пять типов съёмки требуют разных камер и разных параметров полёта. Ограничение совместимости, аналог квалификации в №3, плюс влияние на геометрию галсов.

**4. Расчёт полётных параметров из характеристик.** GSD → высота → ширина захвата → перекрытие → число галсов → время. Обоснованный расчёт, а не «примерно так».

**Главная мысль:** перед производителем дронов нельзя выигрывать покрытием площади — оно у них в продукте. Выигрывать надо тем, чего в типовом планировщике нет: **оптимальным распределением разнородного флота с разных баз по двум критериям, с учётом автономности и совместимости камер.**

### Почему кейс малолюден

⭐ Бизнес 5 в списке малолюдных. Вероятные причины:
- **Трек «БАС»** и заказчик-производитель дронов отпугивают: кажется, что нужен опыт в беспилотниках
- Coverage path planning — не самая известная задача, звучит нишево
- ML-инженер в ролях создаёт ложное впечатление, что нужен ML

Все барьеры преодолимы: CPP и multi-UAV routing — задачи оптимизации, решаются на нашем стеке. Опыт в дронах не нужен, нужны характеристики (их дают) и понимание геометрии покрытия.

## Риски и митигация

| Риск | Митигация (закрываем своими силами, вопросов оргу не будет) |
|---|---|
| Одиночное покрытие галсами не впечатлит Геоскан | Оно фундамент, не цель. Ядро ценности — аллокация разнородного флота по двум критериям, закладывать время на неё |
| Игнорировать автономность БВС | Ограничение L_max — в must-have, это ядро реализма перед производителем дронов |
| Забыть перекрытие снимков | Продольное 60–80%, поперечное 30–60% — проверят первым; без него решение нерабочее |
| Не учесть привязку камеры к типу съёмки | Матрица «тип съёмки → БВС с камерой» — обязательна |
| Уйти в сложную геометрию невыпуклых областей | Начать с выпуклого полигона и довести до конца; невыпуклые и дыры — вторым шагом |
| Неизвестна форма области (простой полигон или сложная с исключениями) | Не спрашиваем: поддерживаем выпуклый как базу, невыпуклый с дырами — как Should; демо готовим на обоих |
| Неизвестен масштаб (сколько БВС, баз, размер области) | Не спрашиваем: генерируем свои сценарии разного масштаба, показываем масштабируемость |
| Неясно, учитывать ли ветер, рельеф, зоны запрета | Не спрашиваем: строим плоскую модель, допущения проговариваем явно на защите — честная и защитимая позиция; запретные зоны как дыры в полигоне |
| Переусложнить оптимизацию | Задача меньше классического VRP; декомпозиция площади + назначение кусков, жадно + локальное улучшение хватит |
| Забыть про два критерия | Оба режима (время/износ) — прямое требование ТЗ, must-have |
| Нет опыта в аэросъёмке | Формулы GSD/перекрытия — открытая методика, разобраться за вечер |

## Стек

- **Геометрия покрытия:** Shapely (разбиение области, галсы, вычитание запретных зон), boustrophedon-декомпозиция
- **Оптимизация назначения:** OR-Tools (задача назначения + маршрутизация с ограничением дальности) или собственная эвристика — задача меньше классического VRP
- **Расчёт полёта:** формулы GSD/высоты/захвата/перекрытия из характеристик (простая арифметика на CPU)
- **Бэк:** FastAPI
- **Фронт:** React + MapLibre GL — область, галсы, маршруты дронов разными цветами, взлётные пункты, точки возврата
- **Визуализация выполнения:** анимация облёта (опционально, но эффектно)

## Приоритизация

**Must:**
- Coverage path planning для выпуклой области (галсы с перекрытием)
- Расчёт параметров полёта из характеристик (GSD → высота → захват → время)
- Ограничение автономности (L_max, при превышении — несколько вылетов)
- Привязка типа съёмки к БВС с нужной камерой
- Декомпозиция + аллокация между несколькими дронами с разных баз
- **Два режима: минимум времени / минимум износа**
- Карта с галсами, маршрутами, метриками

**Should:**
- Невыпуклые области и запретные зоны (дыры)
- Оптимальный угол галсов (минимум разворотов)
- Несколько типов съёмки в одном задании
- Балансировка для makespan
- Сравнение двух режимов бок о бок

**Could:**
- Turn cost для крыла vs мультиротора
- Анимация облёта
- Учёт ветра/рельефа
- Экспорт полётного задания в формат Geoscan/стандартный

**Won't:**
- 3D-облёт рельефа с обходом препятствий по высоте
- Реальная аэродинамика
- Обучение ML-модели

## Демо-сценарий

1. **Проблема, 20 сек.** «Надо отснять территорию: разные типы съёмки, парк из разных дронов, несколько точек взлёта. Вручную распланировать оптимально — долго и неточно.»
2. **Ввод, 20 сек.** Рисуем область на карте, отмечаем взлётные пункты, выбираем дронов из парка, задаём типы съёмки.
3. **План «быстро», 40 сек.** Кнопка «минимум времени». Карта: галсы разных дронов разными цветами, маршруты от баз. Числа: время завершения, суммарный лётный ресурс, кто что снимает.
4. **План «бережно», 30 сек.** Переключаем на «минимум износа». **Тот же участок, другое распределение:** меньше дронов, больше вылетов, дольше по времени, но меньше суммарных часов. Разница в цифрах на экране.
5. **Тип съёмки, 30 сек.** «Этот кусок — мультиспектр». Система назначает только дрон с мультиспектральной камерой, показывает почему.
6. **Автономность, 20 сек.** Большое поле: один дрон не покрывает за вылет → система планирует 2 вылета с возвратом на базу. Видна точка возврата.
7. **Облёт, 20 сек (опционально).** Анимация: дроны летят по галсам, счётчик отснятой площади.

Пункты 3–4 (два критерия) и 5 (камера) — то, что отличит от «покрыли галсами».

## Итоговая оценка

| Критерий | Оценка |
|---|---|
| Требуется ML | **Нет** — оптимизация и геометрия |
| GPU | Не нужен |
| Сервер / деньги на облако | Не нужны — Shapely + OR-Tools на CPU |
| Мало команд | ⭐ **Да** (Бизнес 5) — единственный малолюдный бизнес-кейс на нашем стеке |
| Наш стек | **Да** — Python, Shapely, OR-Tools, геовеб |
| Где настоящая сложность | Декомпозиция + аллокация разнородного флота по двум критериям |
| Что НЕ впечатлит Геоскан | Одиночное покрытие галсами (есть в Geoscan Planner) |
| Что впечатлит | Оптимизация разнородного флота, два критерия, привязка камеры, автономность, корректное перекрытие |
| Барьер | Психологический («БАС», производитель дронов) |
| Главный риск | Высокая планка предметной точности — халтура в GSD/перекрытии/автономности недопустима |
| Жюри | 2 эксперта Геоскан — знают предметку абсолютно, оценят физику, а не UI |
| Эффектность демо | **Высокая** — карта с галсами, два режима, облёт |
| **Итог** | **БЕРЁМ. Позиция 4 в рейтинге «Бизнеса» + малолюдность** |
