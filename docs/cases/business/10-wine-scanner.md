## ТЗ

### Актуальность

Российский винный рынок стремительно трансформируется: доля отечественной продукции превысила 63%, импорт сократился на треть, число винодельческих регионов и ассортимент растут. Потребитель сталкивается с проблемой выбора: международные приложения не содержат актуальных данных именно о российских винах. Платформа «Своё Вино» совместно с рейтингом Роскачества (в 2025 эксперты оценили 800 образцов, отобрали вина выше 83 баллов) предлагает достоверный цифровой гид. Согласно опросу «Винный Барометр», почти половина россиян предпочитает отечественное вино и готова рекомендовать его — запрос на удобный инструмент оценки качества прямо в точке продажи.

Сканер становится стратегическим решением для популяризации винной культуры, поддержки малых производителей и развития энотуризма.

## Что даёт организатор и что это значит

**Дают:** массив данных о винах с платформы «Своё Вино» — карточки с описанием, названием, производителем, вероятно с фото этикеток. Это **база для поиска**, а не размеченный training set для обучения классификатора вин.

Задача сформулирована как retrieval: «после сканирования по фотографии найти нужную карточку». То есть **сопоставить фото этикетки с карточкой в базе** — это поиск, а не классификация «что это за вино» обученной моделью. Обучение не нужно, GPU не нужен.

### Разведка платформы

- **«Своё Вино»** (vino-svoe.ru) — запущена РСХБ, анонс 14.10.2025. Позиционируется как «самый полный каталог российских вин» с народным рейтингом. **Сканер этикеток УЖЕ заявлен штатной функцией портала** — команда фактически улучшает существующий функционал. Каталог: например, Крым — 756 вин; всего тысячи. В карточках — фото, название, винодельня, регион, рейтинг
- **API** платформы публично не подтверждён — данные, вероятно, придётся получать дампом от заказчика либо **парсить портал своими силами**
- **Роскачество «Винный гид России 2025»:** >800 образцов, порог 83 балла, публикуется открыто на rskrf.ru (названия, производители, годы, баллы). Готового датасета с фото нет — использовать как справочник названий/баллов/описаний

**Важное следствие:** раз сканер уже есть на портале, заказчику интересно **улучшение** — точность, устойчивость к плохим фото, скорость. Отрыв — в work-rate на реальных фото и в качестве карточки-результата.

## Кто судит и что это меняет

- **Не CV-специалисты, а финтех/продукт/контент.** В отличие от Фалькона (№7, профильное CV-жюри), здесь оценят **продукт и точность попадания**, а не изящество модели. Планка ниже

**Практический вывод:** упор на демо с **реальными** фото бутылок (не идеальными студийными) и на красивую информативную карточку. Не на сложность модели.

## Как решать

### Главная поправка: чистый OCR недостаточен, нужен гибрид

Гипотеза «прочитать этикетку OCR и найти по тексту» верна по инструментам, но **опасна как единственный канал**.

**Почему чистый OCR ломается на винных этикетках:**
- блики на глянце
- изогнутая (цилиндрическая) поверхность бутылки — текст «уплывает»
- декоративные и рукописные шрифты
- тиснение без контраста (текст того же цвета, что фон)
- образные этикетки вообще без читаемого названия

**Как устроен эталон отрасли (Vivino):** ядро — **image retrieval** (сравнение фото с эталонными снимками этикеток в базе), а OCR добавлен **сверху** для дизамбигуации. Match rate вырос **48% → 86% именно после добавления OCR к визуальному матчингу** — каналы дополняют друг друга, а не заменяют.

**Вывод:** «тяжёлый CV» (обучение своей сети) не нужен. Но нужен **готовый visual matching без обучения** (pretrained-эмбеддинги) ПЛЮС OCR, а не один OCR.

### Почему это НЕ похоже на Re-ID (№7), хотя оба про фото

| | Б№7 Re-ID авто | Б№10 Сканер вин |
|---|---|---|
| Что различаем | Два одинаковых авто одной модели | Этикетки — **у каждого вина уникальный текст и уникальный дизайн** |
| Главный признак | Тонкие визуальные (нужен дообученный эмбеддинг) | **Текст на этикетке (OCR) + визуальный дизайн** |
| Обходной путь | Слабый без дообучения | **Сильный — гибрид на готовых моделях** |
| Обучение | Дообучение почти обязательно | **Не нужно** |
| Жюри | Профильное CV | Финтех/контент — не CV |

Текст этикетки — **сильный уникальный признак**, а не тонкое различие двух одинаковых объектов. Это переводит задачу из тяжёлого CV в retrieval на готовых моделях.

### Правильная архитектура: два канала → rerank

**Retrieve (два параллельных канала, recall-heavy):**
1. **Визуальный:** эмбеддинг фото (DINOv2 ViT-B или CLIP) → top-K из FAISS
2. **Текстовый:** PaddleOCR → нормализация → RapidFuzz top-K по названиям

**Rerank (precision):** слить кандидатов, переранжировать по сумме визуального сходства + fuzzy-score. При ничьей — дизамбигуация по OCR-полям (год, регион, объём).

**Верификация топ-1 (опция):** ORB + гомография между фото и эталоном — отсечь ложные срабатывания.

Это стандартная схема retail product recognition 2026 (fuzzy + vector embeddings → merge/rerank) и совпадает по духу с Vivino.

### Стек по слоям — всё на CPU, без обучения

| Слой | Инструмент | Цифры |
|---|---|---|
| Препроцессинг | OpenCV: выравнивание перспективы, **cylindrical dewarping** по 6 точкам, бинаризация | dewarping даёт OCR-точность до **98.25%** vs плохой на изогнутом |
| OCR | **PaddleOCR (PP-OCRv4/v5 mobile)**, рус+англ | лидер на кириллице, **0.5–1 с/фото** на CPU. EasyOCR — запасной. Tesseract слаб на этикетках |
| Визуальные эмбеддинги | **DINOv2 ViT-B** (ONNX на CPU) | **25–35 мс/фото**. DINOv2 > CLIP на fine-grained сходстве |
| Локальные фичи | **ORB/AKAZE + гомография** (OpenCV) | без обучения, для точного «та же этикетка», устойчивы к образным без текста |
| ANN-индекс | **FAISS / hnswlib** | мгновенно на сотнях–тысячах вин |
| Fuzzy-матч | **RapidFuzz** | C++/SIMD, token_sort_ratio, порог под OCR-шум |
| Нормализация | своя: транслит кириллица↔латиница, снятие годов/объёма/«кр.сух.» | критично для кириллицы |

**Скорость всего пайплайна: 1–2 с/фото на CPU** — приемлемо для веб-сервиса. GPU не нужен. Все модели pretrained — ни одной эпохи обучения.

### Развилка: есть ли фото этикеток в базе

Это определяет архитектуру:
- **Если фото есть** → работает гибрид (визуальный канал + OCR) → надёжный сканер
- **Если только текст** → визуальный канал недоступен, остаётся **OCR-only** → рабочий MVP, но низкий потолок надёжности на бликах/декоре

**Закрываем своими силами:** в карточках портала vino-svoe.ru **изображения этикеток есть** (название, винодельня, регион, стиль, рейтинг), плюс rskrf.ru Роскачества. Парсим сами, вопрос организатору не требуется. Fallback — честный OCR-only MVP с оговоркой.

### Дубликаты и винтажи — тонкость, которую надо показать

Одно вино разных годов урожая — почти одинаковые этикетки. Визуальный матч их не различит.

**Решение:** OCR обязателен для дизамбигуации винтажа. В карточке: «вино найдено, уточните год». Похожие этикетки серии одного производителя — отсекать реранком + ORB-верификацией.

Неочевидная деталь, которую оценит контент-руководитель РСХБ — она знает структуру карточек и понимает проблему годов урожая.

### Главный убийца сканеров — реальные условия съёмки

Демо-фото ≠ фото с полки магазина: рука, перспектива, фон, блик, плохой свет.

**Митигация:**
- тестировать на 30–50 «грязных» фото с телефона **заранее**, а не на студийных
- гайд по съёмке в UI (контраст, ракурс, держать ровно) — как делает InVintory
- визуальный канал устойчивее к бликам, чем OCR — ещё аргумент за гибрид
- топ-N кандидатов при неуверенности, пользователь выбирает (human-in-the-loop)

## Где выигрывается / что даёт отрыв

- **Точность попадания** — метрика «отсканировал N бутылок, попал в правильную карточку в M% случаев». Прямая ценность, измеримая
- **Обработка плохих фото** — блики, изгиб, ракурс. **Ключевой дифференциатор:** сканер на портале уже есть, выигрывает тот, кто устойчив к реальным условиям магазина
- **Топ-кандидатов при неуверенности** — если матч неоднозначен, показать несколько вариантов с объяснением (human-in-the-loop)
- **Быстрота** — сканер в точке продажи должен работать за секунды; 1–2 с/фото достижимо
- **Обогащение карточки** — не только найти, но красиво показать: рейтинг Роскачества (вина выше 83 баллов), описание, регион, винодельня. Контентная ценность, которую оценит контент-руководитель
- **Дизамбигуация винтажа** — деталь, показывающая понимание предметки
- **Мобильность** — сканирование по фото подразумевает телефон в магазине. Веб с камерой или мобильный интерфейс

## Стек

- **OCR:** PaddleOCR (PP-OCRv4/v5 mobile, рус+англ) — предобучен, CPU, 0.5–1 с/фото; EasyOCR запасной
- **Препроцессинг:** OpenCV — выравнивание перспективы, cylindrical dewarping, бинаризация, устранение бликов
- **Визуальные эмбеддинги:** DINOv2 ViT-B через ONNX на CPU (25–35 мс/фото); CLIP как альтернатива
- **Локальные фичи:** ORB/AKAZE + гомография (OpenCV) для верификации топ-1
- **ANN-индекс:** FAISS / hnswlib
- **Текстовый матч:** RapidFuzz (token_sort_ratio), своя нормализация (транслит кириллица↔латиница, снятие годов/объёма/«кр.сух.»)
- **Бэк:** FastAPI
- **Фронт:** React / мобильный веб — камера, скан, карточка результата, топ-N кандидатов
- **Данные:** массив «Своё Вино» (дамп или парсинг vino-svoe.ru) + справочник Роскачества (rskrf.ru)

## Приоритизация

**Must:**
- OCR (PaddleOCR) + нормализация + RapidFuzz по названиям
- База вин с индексом (текст обязательно, фото если есть)
- Препроцессинг (выравнивание, базовое устранение бликов)
- Карточка-результат с данными платформы
- Топ-N кандидатов при неуверенности
- Веб/мобильный интерфейс с камерой

**Should (если есть фото этикеток):**
- Визуальный канал: DINOv2/CLIP эмбеддинг + FAISS
- Гибридный rerank (визуал + текст)
- Cylindrical dewarping для изогнутых бутылок
- Дизамбигуация винтажа по OCR
- Замер метрики попадания на 30–50 реальных фото

**Could:**
- ORB-гомография для верификации топ-1
- Обогащение карточки рейтингом Роскачества
- Гайд по съёмке в UI
- Устранение бликов (U²-Net) — тяжелее

**Won't:**
- Обучение/дообучение эмбеддингов (без GPU не браться)

## Демо-сценарий

1. **Проблема, 20 сек.** «Покупатель в магазине видит российское вино, но не знает, хорошее ли. Международные приложения российские вина не знают.»
2. **Скан, 30 сек.** Навёл камеру на бутылку (реальную, не студийную) → через 1–2 сек карточка вина.
3. **Карточка, 30 сек.** Название, винодельня, регион, **рейтинг Роскачества** (83+ балла), описание. Красиво и информативно.
4. **Плохое фото, 30 сек — ключевой момент.** Блик / кривой ракурс / изогнутая этикетка → система всё равно находит (визуальный канал) или показывает топ-3 кандидата. «Работает в реальных условиях магазина.»
5. **Винтаж, 20 сек.** Два года одного вина → «уточните год» с разбором по OCR.
6. **Метрика, 15 сек.** «На N реальных фото — попадание в топ-1 в M%, в топ-3 в K%.»

Пункт 4 (устойчивость к плохим фото) — то, что отличит от наивного сканера и попадёт в «улучшение существующего».
