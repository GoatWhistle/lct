# ЛЦТ 2026 — обзор всех кейсов и выбор

Международный хакатон «Лидеры цифровой трансформации 2026». Разобраны **все кейсы обоих направлений**: 10 «Город» + 10 «Бизнес». Призовой фонд каждого кейса одинаков: **1 место — 1 000 000 ₽, 2 место — 600 000 ₽, 3 место — 400 000 ₽.**

Сроки: заявка до **14 сентября**, разработка **15–29 сентября** (две недели). Организатор просит выбирать кейс раньше дедлайна — в последний день возможны баги платформы.

---

## Вводные команды (главный фильтр)

1. **Нет сервера, нет GPU, нет денег на аренду облака.** Всё работает на ноутбуке (CPU, 8–16 ГБ RAM). Исключено: обучение нейросетей, аренда GPU, тяжёлый инференс.
2. **Облачный LLM-API разрешён** — это не сервер, обычные дешёвые вызовы. Локальные модели на CPU — только лёгкие (эмбеддинги model2vec, OCR PaddleOCR, STT GigaAM, TTS Silero).
3. **Вопросов организатору не будет** — никто не ответит. Любая неизвестность о данных — риск, который закрываем сами (синтетика, открытые источники, парсинг, заглушки).
4. **Команда:** Python/веб (FastAPI, React), сильны в бэкенде/аналитике/алгоритмах. **Нет:** ML-инженера, дизайнера, геймдизайнера.

**Два производных правила оценки:**
- *Локальность:* работает ли ПОЛНОСТЬЮ на ноутбуке без сервера и без обучения модели
- *Самодостаточность риска:* закрывается ли неизвестность данных нашими силами БЕЗ вопроса оргам

## Ключевые закономерности (по всем 20 кейсам)

### 1. Диагностический критерий — смотри, что даёт организатор

Работает точнее чтения заголовка. Реальный неустранимый ML только в двух кейсах из двадцати.

| Что выдают | Значит | Примеры |
|---|---|---|
| **Датасет с экспертной разметкой** | ML неустраним | Город №4 |
| Логи с полем результата | ML законен, но табличный (CPU) | Город №8 |
| Справочники, нормы, методики | Задача детерминированная | Город №1, №3; Бизнес №1, №9 |
| Ссылки на готовые датасеты | Готовые веса, без обучения | Город №7 |
| База для поиска | Retrieval на готовых моделях | Бизнес №8, №10 |
| Inference API + примеры | Оркестрация, не обучение | Бизнес №4 |
| Характеристики / параметры | Оптимизация | Бизнес №3, №5 |
| Сырьё без разметки | ML не нужен, но метрики не измерить — нужен свой эталон | Город №5, №10; Бизнес №1 |
| **Физический объект (плата)** | Не наш профиль | Бизнес №2 |

### 2. «ИИ» в заголовке ≠ требуется ML

Слово «ИИ»/«ML» встречается примерно в половине кейсов, реально обучение нужно в двух. В остальных «ИИ» = LLM через API, готовые веса или методическая формулировка. **Это главная возможность: кейсы малолюдны из-за психологического барьера, а не технического.**

### 3. Состав жюри предсказывает критерии

| Тип жюри | Кейсы | Что оценивают |
|---|---|---|
| Аналитики / экономисты | Город №1, Бизнес №1 | Обоснованность модели |
| Методисты (0 технарей) | Город №3, №6, №9 | Соответствие нормам, педагогику |
| Инженеры-практики | Город №5, Бизнес №4, №8 | Техническую состоятельность |
| Продуктовики | Бизнес №3, №10 | Полезность, work-rate |
| Дизайнеры / геймдизайнеры | Бизнес №9 | Концепцию, UX |
| Профильные CV / hardware | Город №4, Бизнес №2, №7 | По меркам индустрии (барьер) |

**Правило:** чем меньше технарей в жюри, тем важнее продукт и методика; чем больше профильных — тем выше планка и меньше права на ошибку.

### 4. Победная стратегия везде одна — объяснимость вместо чёрного ящика

Заказчики — госорганы и корпорации, им нужно обосновывать решения. Во всех топ-кейсах выигрывает раскрытие «почему»: формула и источник (Город №1, Бизнес №1), соответствие нормативу (Город №3), кадр-доказательство (Город №7), метрики ГОСТ (Город №9), drill-down до данных (Бизнес №8), декомпозиция стоимости маршрута (Бизнес №3).

### 5. Требования, которые все игнорируют — самый дешёвый отрыв

Когда в ТЗ упомянут норматив, регламент или закон, большинство команд считает это формальностью и пропускает. А написал это тот, кто сидит в жюри.

- **Бизнес №6:** 152-ФЗ и приказ ФСТЭК №117 (вступил в силу 01.03.2026, заменил проработавший 10+ лет приказ №17). Демонстрируемая часть — RBAC, журнал аудита обращений к ПДн, обезличенный режим аналитики, учёт согласий — реализуема за хакатон и даёт отрыв, которого больше взять негде
- **Город №9:** ГОСТ Р 22.7.03-2021 задаёт метрики автооценки (опрос ≤ 75 сек) — ссылка на действующий норматив весит больше «мы придумали критерии»
- **Город №3:** нормативы названы поимённо (743-ПП, 623-ПП, СП 42.13330.2016) — построчная таблица соответствия бьёт точно в критерии
- **Город №2:** веса графа из официальных НЦС 81-02-13-2025 и СП 124 табл. А.3 вместо выдуманных коэффициентов

### 6. KPI заказчика — часто сроки

Город №3 («срок инвестиционного цикла»), Город №10 («сроки проверок»), Город №2 («длительные согласования»), Бизнес №3 (SLA), Бизнес №6 («сокращение трудозатрат»). Метрика «было N дней — стало M минут» весит больше технического качества.

## Что решило исход под жёсткими вводными

Правило «ноутбук без сервера и без обучения» отсекает только два кейса (Город №4, Бизнес №2 — плюс Бизнес №7 после потери аренды GPU).

**Настоящая дифференциация — по самодостаточности риска.** Топ-кейсы выигрывают тем, что их неизвестности закрываются нашими руками: открытые нормативы (ГОСТ для №9, НЦС/СП для №2), синтетика (лидар, DXF), открытые источники (arXiv/OpenAlex для трендов, OSM для гео, веб-камеры для стройки), собственный парсинг (порталы вина).

**Город №8 (коллекторы) провалился в нижнюю зону именно потому**, что его главный риск — численный порог приёмки — единственный, который своими силами не закрывается.
