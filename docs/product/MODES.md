# Режимы, подсказки, прогресс

Формат сценария (`modes`): [../spec/SCENARIO-FORMAT.md](../spec/SCENARIO-FORMAT.md) · Разбор и отчёт: [DEBRIEF.md](DEBRIEF.md) · События контракта: [../arch/CONTRACT.md](../arch/CONTRACT.md)

## Три режима сессии

Режим задаётся при запуске сессии преподавателем (или курсантом — для самостоятельного) и действует до конца занятия. Режим ортогонален упражнению (ДДС, 112 по текстовой вводной, голосовой вызов). Один и тот же сценарий проходит в любом режиме без перенастройки; режим меняет доступность подсказок и отметку в истории, но не поведение звонящего.

| | Тренировочный | Контрольный | Самостоятельный |
|---|---|---|---|
| Кто запускает | преподаватель | преподаватель | преподаватель или курсант по назначенному модулю |
| Подсказки | по запросу курсанта | **недоступны** | по запросу курсанта |
| Директивы преподавателя | да | да (по его решению) | нет |
| Цель | научить | измерить | наработать |
| Результат | в профиль, виден преподавателю | в профиль, фиксируется как контрольный | в профиль |

Контрольный — это экзамен: подсказки запрещены на сервере, результат в истории профиля помечается как контрольный. Радар профиля считается по всем попыткам без разделения по режимам.

## Подсказка по запросу

В тренировочном и самостоятельном режимах у курсанта есть кнопка «Подсказка» — только в упражнении с опросом звонящего: в упражнениях ДДС и заполнения КИО по вводной сервер запрос подсказки отклоняет. Нажатие раскрывает **следующий неотработанный вопрос чек-листа** — не список целиком, а один шаг: «уточните, есть ли люди в помещении».

Принципы:

- **курсант сам решает, когда подсказаться** — тренажёр не подсказывает навязчиво и не стыдит за запрос; умение вовремя запросить опору — часть обучения;
- **подсказка по запросу — признание пробела.** Каждое использование фиксируется в сессии: какой пункт, на какой минуте. В разбор попадает список использованных подсказок;
- **без автоматического штрафа.** Счёт подсказок — информация для преподавателя и разбор, а не вычитаемое из баллов: решение, как это влияет на итог, остаётся за человеком;
- в контрольном режиме кнопки нет — и это часть нормы контроля: на экзамене опоры нет.

Реализация детерминированная: сервер по слот-автомату знает, какие пункты чек-листа закрыты, и отдаёт следующий неотработанный и ещё не показанный; без модели эмбеддингов — по порядку чек-листа ([../arch/BACKEND.md](../arch/BACKEND.md)). Никакого LLM в выдаче подсказки.

## Самостоятельный режим

Курсант может стартовать сессию без преподавателя: из назначенного ему учебного модуля, к которому привязан сценарий, запускается упражнение 112 по текстовой вводной (заполнение КИО) в режиме `self`. Каталог курсанта показывает только сценарии с `modes: [self]`, без эталона. Ход тот же: карточка, оценка, разбор. Преподаватель может запустить самостоятельный режим и сам.

- результат падает в профиль курсанта и виден преподавателю в истории — самостоятельная работа не исчезает, а встроена в картину подготовки;
- директив преподавателя нет; сложность регулируется выбором сценария;
- это «домашняя работа», а не контроль: в профиле помечается как самостоятельная.

Отдельного ограничения числа одновременных сессий в коде нет: все живут в памяти одного воркера. Узкое место — голосовой контур на CPU, он ограничен по числу одновременных разговоров; основная форма работы — групповое занятие ([METHODOLOGY.md](METHODOLOGY.md)).

## Повтор сценария и дельта попыток

Все попытки по сценарию сохраняются. В профиле курсанта по каждому сценарию:

- список попыток с итогами;
- **дельта между попытками**: итоговая оценка, время опроса, число добытых фактов — что изменилось от попытки к попытке; коды ошибок каждой попытки видны в истории.

Работа над ошибками превращается в измеримый цикл: посмотрел разбор → попробовал снова → увидел дельту. Это и есть «развивать и совершенствовать навыки» из ТЗ, сделанное механикой, а не лозунгом.

## Профиль курсанта

Личная страница курсанта:

- **радар компетенций** — шесть навыков ([METHODOLOGY.md](METHODOLOGY.md)), среднее по попыткам;
- **история сессий** — дата, режим, попытка, сценарий, оценка, время опроса, факты, подсказки, коды ошибок; ссылки на разбор и запись WAV, если она есть; фильтров нет;
- **рекомендации к следующему занятию** — до пяти действий по кодам ошибок последней оценённой попытки; формулировки совпадают с рекомендациями аналитики группы;
- **использованные подсказки** — общее число и число по каждой попытке;
- **PDF-сертификат** — при наличии хотя бы одной оценённой попытки.

Автоматических «сильных/слабых сторон» и сводки пометок преподавателя в профиле нет: пометки видны в разборе конкретной сессии.

Преподаватель видит профиль любого курсанта своей группы; курсант — свой. Профиль вместе с аналитикой группы закрывает «контроль подготовленности» из ТЗ не как таблицу оценок, а как инструмент планирования подготовки.
