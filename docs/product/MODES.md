# Режимы, подсказки, прогресс

Формат сценария (`modes`): [../spec/SCENARIO-FORMAT.md](../spec/SCENARIO-FORMAT.md) · Разбор и отчёт: [DEBRIEF.md](DEBRIEF.md) · События контракта: [../arch/CONTRACT.md](../arch/CONTRACT.md)

## Три режима сессии

Режим задаётся при запуске сессии преподавателем (или курсантом — для самостоятельного) и действует до конца звонка. Один и тот же сценарий проходит в любом режиме без перенастройки; режим меняет доступность подсказок и протоколирование, но не поведение звонящего.

| | Тренировочный | Контрольный | Самостоятельный |
|---|---|---|---|
| Кто запускает | преподаватель | преподаватель | курсант сам |
| Подсказки | по запросу курсанта | **недоступны** | по запросу курсанта |
| Директивы преподавателя | да | да (по его решению) | нет |
| Цель | научить | измерить | наработать |
| Результат | в профиль, виден преподавателю | в профиль, фиксируется как контрольный | в профиль |

Контрольный — это экзамен: строгое протоколирование, результат отмечается как контрольный и в профиле отделён от тренировочных попыток.

## Подсказка по запросу

В тренировочном и самостоятельном режимах у курсанта есть кнопка «Подсказка». Нажатие раскрывает **следующий неотработанный вопрос чек-листа** — не список целиком, а один шаг: «уточните, есть ли люди в помещении».

Принципы:

- **курсант сам решает, когда подсказаться** — тренажёр не подсказывает навязчиво и не стыдит за запрос; умение вовремя запросить опору — часть обучения;
- **подсказка по запросу — признание пробела.** Каждое использование фиксируется в сессии: какой пункт, на какой минуте. В разбор попадает список использованных подсказок;
- **без автоматического штрафа.** Счёт подсказок — информация для преподавателя и разбор, а не вычитаемое из баллов: решение, как это влияет на итог, остаётся за человеком;
- в контрольном режиме кнопки нет — и это часть нормы контроля: на экзамене опоры нет.

Реализация детерминированная: сервер по слот-автомату знает, какие пункты чек-листа закрыты, и отдаёт следующий неотработанный ([../arch/BACKEND.md](../arch/BACKEND.md)). Никакого LLM в выдаче подсказки.

## Самостоятельный режим

Курсант может стартовать сессию без преподавателя: из библиотеки доступны сценарии с `modes: [self]` (открытые преподавателем для самостоятельной отработки). Ход тот же: звонок, карточка, оценка, разбор.

- результат падает в профиль курсанта и виден преподавателю в истории — самостоятельная работа не исчезает, а встроена в картину подготовки;
- директив преподавателя нет; сложность регулируется выбором сценария;
- это «домашняя работа», а не контроль: в профиле помечается как самостоятельная.

Параллельные сессии нескольких курсантов не строятся: голосовой контур на CPU ограничен по числу одновременных разговоров, а основная форма работы — групповое занятие ([METHODOLOGY.md](METHODOLOGY.md)).

## Повтор сценария и дельта попыток

Все попытки по сценарию сохраняются. В профиле курсанта по каждому сценарию:

- список попыток с итогами;
- **дельта между попытками**: время опроса, полнота чек-листа, коды ошибок — что изменилось от попытки к попытке.

Работа над ошибками превращается в измеримый цикл: посмотрел разбор → попробовал снова → увидел дельту. Это и есть «развивать и совершенствовать навыки» из ТЗ, сделанное механикой, а не лозунгом.

## Профиль курсанта

Личная страница курсанта:

- **радар компетенций** — шесть навыков ([METHODOLOGY.md](METHODOLOGY.md)); при нескольких попытках — динамика;
- **история сессий** — тренировочные, контрольные, самостоятельные; фильтр по сценарию и периоду;
- **сильные/слабые стороны** — собираются из радара автоматически: «устойчиво превышает норматив опроса на медицинских вызовах»;
- **использованные подсказки** — какие и как часто;
- **пометки преподавателя** — из всех сессий, словами преподавателя.

Преподаватель видит профиль любого курсанта своей группы; курсант — свой. Профиль вместе с аналитикой группы закрывает «контроль подготовленности» из ТЗ не как таблицу оценок, а как инструмент планирования подготовки.
