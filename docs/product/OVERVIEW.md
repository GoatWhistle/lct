# Продукт — учебный симулятор занятия для системы 112

Разбор требований заказчика: [../spec/TZ.md](../spec/TZ.md) · Нормативы: [../spec/NORMATIVES.md](../spec/NORMATIVES.md) · Симуляция звонка: [CALL-SIM.md](CALL-SIM.md) · Методика: [METHODOLOGY.md](METHODOLOGY.md) · Разбор: [DEBRIEF.md](DEBRIEF.md) · Режимы: [MODES.md](MODES.md)

## Что строим

Веб-система для проведения занятий по подготовке операторов 112 и диспетчеров ДДС:

- **живой звонок с ИИ-звонящим** — голос в обе стороны, звонящий играет происшествие по сценарию и не выдаёт данные сам;
- **АРМ оператора по нормативу** — карточка КИО, таймеры ГОСТ Р 22.7.03-2021;
- **объективная оценка с обоснованием** — детерминированные метрики по нормативу + разбор каждой ошибки;
- **полный учебный контур** — эталонный звонок с автопроигрыванием, подсказки по запросу, самооценка, таксономия ошибок, профиль и прогресс курсанта;
- **рабочее место преподавателя** — ведение ситуации в реальном времени и управление занятием.

Принцип: строим **тренажёр занятия**, а не «оценку за звонок». Один курсант работает, группа смотрит на внешнем мониторе, преподаватель ведёт ситуацию, разбор — учебный момент для всех.

## Для кого

- **Преподаватель УМЦ ГО ЧС** — проводит занятие: задаёт сценарий, управляет ситуацией, получает готовый разбор вместо ручного прослушивания записей, видит, что разбирать с группой.
- **Курсант-оператор 112** — тренирует приём вызова: опрос, заполнение КИО, классификацию, работу с трудным звонящим; в самостоятельном режиме — сам.
- **Курсант-диспетчер ДДС** — тренирует приём карточки, подтверждение по нормативу, решение о зоне ответственности.
- **Группа** — смотрит на внешнем мониторе, учится на чужом разборе.

## Интерфейсы

| Экран | Кто | Суть |
|---|---|---|
| АРМ курсанта | оператор 112 | Входящий вызов, гарнитура, карточка КИО, таймеры, кнопка подсказки |
| Пульт преподавателя | преподаватель | Выбор сценария и режима, ход сессии, директивы звонящему, пометки в транскрипте |
| Внешний монитор | группа | Read-only: ход разговора, заполнение карточки, разбор, эталон-плеер; читается с последнего ряда |
| АРМ ДДС | диспетчер ДДС | Карточка от оператора, подтверждение ≤ 4 с, возврат на уточнение, отметки времени |

Архитектура интерфейсов: [../arch/FRONTEND.md](../arch/FRONTEND.md); разделение прав и каналов — [../arch/CONTRACT.md](../arch/CONTRACT.md).

## Ядро продукта — не режется никогда

1. Сквозной голосовой контур: позвонили → поговорили голосом → заполнили карточку → получили оценку. Один сценарий целиком раньше всего остального.
2. Карточка КИО по структуре норматива.
3. Детерминированная оценка по ГОСТ с обоснованием каждой метрики.
4. Звонящий, который не отдаёт данные сам.
5. Разбор после звонка: транскрипт с отметками ошибок и эталонными вопросами.

Всё остальное наращивается поверх работающего ядра.

## Приоритеты

> **Пересмотрены 18.09.2026 по полному ТЗ заказчика** ([../spec/TZ-FULL.md](../spec/TZ-FULL.md), разбор — [../spec/GAP.md](../spec/GAP.md)). Прежний список строился по короткому описанию с лендинга и отправлял под нож ровно то, что заказчик назвал поимённо: генератор сценариев — это его сценарий «Настройка учебной среды», аналитика группы — названная возможность преподавателя.

### Must — учебное ядро (сделано)

- Голосовой контур, КИО, оценка по ГОСТ
- Чек-листы опроса + подсказка по запросу, режимы тренировочный / контрольный / самостоятельный
- Таксономия ошибок E1–E6, эталонный диалог, самооценка до автооценки
- Повтор сценария с дельтой попыток, профиль курсанта с радаром
- Пульт преподавателя: сценарий, наблюдение, пометки, директивы
- Внешний монитор, АРМ ДДС, разбор
- Работа без внешних сетей: распознавание, синтез, VAD, эмбеддинги локально; звонящий офлайн по предгенерированной таблице

### Must — названо в ТЗ, не сделано

- **Аутентификация, роли и аудит действий** (администратор, преподаватель, обучающийся)
- **Роль администратора**: учётные записи, состояние сервисов, резервное копирование, журналы
- **Второй режим занятия**: поток карточек с вводом текста и его оценкой, включая грамматику
- **Генерация сценариев** с предпросмотром, подтверждением и коррекцией комментарием преподавателя
- **Аналитика группы**: типичные ошибки, рекомендации системы
- **Настраиваемые преподавателем тайминги и пороги** (по умолчанию 30 с)
- **Экспорт отчётности** в CSV и PDF
- **Сопроводительная документация** — она прямо входит в критерий «соответствие решения задаче»

### Should

- SIP-шлюз рядом с контуром: «локальный SIP-сервер» из раздела совместимости ([../arch/STACK.md](../arch/STACK.md))
- Звонящий, скрывающий информацию; персоны «ребёнок» и «иностранец»
- Автопроигрывание эталонного звонка, аудио-фон происшествия
- Запись вызовов в MP3/WAV, сертификаты PDF
- Мобильная версия интерфейса

### Could

- ЭРА-ГЛОНАСС, программы занятий, горизонтальное масштабирование

**Порядок отсечения, если не влезает.** Первыми жертвуются вещи, которых нет в ТЗ: ЭРА-ГЛОНАСС, программы занятий, персоны. Затем SIP-шлюз — он закрывает одну строку раздела совместимости, тогда как заказчик сам допускает программную эмуляцию IP-телефона. Затем запись вызовов и сертификаты.

**Не режется:** учебное ядро (подсказки, эталон, самооценка, таксономия, режимы, пульт с директивами) и всё, что заказчик назвал поимённо в пользовательских сценариях и ролях — вход с ролями, второй режим занятия, генератор, аналитика группы, документация.

## Definition of Done

Функция считается сделанной, когда выполнено всё:

| Требование | Критерий приёмки |
|---|---|
| Сквозной голосовой контур | Задержка от конца реплики оператора до первого звука ответа ≤1.5 с, измерена, цифра записана |
| АРМ курсанта с карточкой КИО | Все группы полей норматива присутствуют; поля валидируются; заполнение уходит в БД и наблюдателям |
| Один сценарий от звонка до оценки | Прогоняется подряд 5 раз без ручного вмешательства и падений |
| Детерминированная оценка по ГОСТ | Каждая метрика показана как «факт против норматива со ссылкой» |
| Разбор с эталоном | По каждому пропущенному пункту чек-листа видно, какой вопрос был эталонным |
| Подсказки | В тренировочном режиме раскрываются по запросу курсанта, в контрольном недоступны; использования зафиксированы в разборе |
| Режимы | Один и тот же сценарий проходит в тренировочном и контрольном режиме без перенастройки кода |
| Пульт преподавателя | Выбор сценария и режима, запуск, наблюдение без вмешательства в разговор и карточку |
| Повтор сценария | Две попытки по одному сценарию видны в профиле с дельтой метрик |
| Самооценка | Курсант оценил себя до показа автооценки; расхождение видно преподавателю |
