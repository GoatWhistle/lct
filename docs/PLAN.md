## Форма репозитория

```
lct-hack/
├── backend/            # FastAPI, голосовой контур, оценка, БД     → plan/BACKEND.md
├── frontend/           # React SPA, четыре интерфейса              → plan/FRONTEND.md
├── scenarios/          # YAML-библиотека сценариев (контент, не код)
├── docs/               # этот план, разбор кейса, нормативка, питч
├── docker-compose.yml  # postgres + backend + frontend, одна команда на подъём
├── Makefile            # make dev / make types / make seed / make demo
└── README.md           # как поднять за 3 команды — это читает эксперт на заочке
```

Монорепа, одна ветка `main`, работа через короткие ветки `feat/<зона>-<что>` и PR без ревью-церемоний (смотрит владелец соседней зоны, если задет контракт). Merge-очередь не нужна — зоны почти не пересекаются, единственный общий шов описан в [CONTRACT.md](plan/CONTRACT.md).

**Сценарии лежат в корне, а не в backend/** — их правит лид, и это контент, а не код. Формат — YAML, читается человеком, ревьюится глазами.

## Пять треков и владельцы

| Трек | Кто | Зона в репозитории | Главный артефакт |
|---|---|---|---|
| **A. Голосовой контур** | Бэкенд+архитектура | `backend/app/voice/`, `backend/app/api/ws/` | Звонок звучит в оба конца за ≤1.5 с |
| **B. Диалог и оценка** | AI-инженер | `backend/app/dialog/`, `backend/app/scoring/` | Звонящий не отдаёт данные сам; оценка с обоснованием |
| **C. Данные и преподаватель (бэк)** | Бэкенд (второй) | `backend/app/db/`, `backend/app/scenarios/`, HTTP-API | Библиотека, сессии, история, observer-поток |
| **D. Интерфейсы** | Фронтенд | `frontend/` целиком | АРМ курсанта, пульт преподавателя с вбросами, внешний монитор, АРМ ДДС |
| **E. Содержание и защита** | Лид | `scenarios/`, `docs/` | 8 эталонных сценариев, нормативные обоснования, внешний монитор, питч |

**Узкое место — трек D: один человек на четыре интерфейса.** Митигация заложена в календарь: внешний монитор (`wallboard`) намеренно спроектирован как read-only-экран на тех же событиях, что и пульт преподавателя, — его пишет лид по готовым компонентам фронта на второй неделе. АРМ ДДС собирается из готовых компонентов и не содержит аудио-кода. Порядок отсечения, если не успеваем: агрегат группы → генератор → АРМ ДДС (крайний срок решения 24.09). **Пульт вбросов не режется никогда** — это основной отрыв ценой в полдня.

**У AI-инженера первая неделя без фронта.** Трек B до 18.09 живёт в консоли: `make repl` — текстовый диалог со звонящим без голоса. Так персона и слот-автомат отлаживаются, пока контур ещё не собран.

## Правило вертикального среза

Из [DECISION.md](DECISION.md), повторяю, потому что это единственное правило, нарушение которого топит проект:

> **К концу 16.09 один сценарий должен проходить целиком:** позвонили → поговорили голосом → заполнили карточку → получили оценку. Даже криво, на одном захардкоженном сценарии, без стилей.

Всё остальное — библиотека, уровни, пульт преподавателя, внешний монитор, разбор, офлайн — наращивается **поверх работающего среза**. Начинать с красивого интерфейса преподавателя или с двадцати сценариев — ловушка, названная в разборе кейса.

## Чем отрываемся

Голосовой контур, карточка, оценка по таймерам, панель преподавателя и библиотека сценариев — **это база, а не отрыв.** Её построит любая команда, прочитавшая «описание задачи»; TTS и STT сегодня коммодити, и аргумент «Sim911 текстовый, а мы голосом» продержится до второго выступления, где тоже будет голос.

Отрыв даёт переформулировка продукта. Все двадцать команд строят **тренажёр оператора** — один курсант, один звонок, оценка. Мы строим **тренажёр занятия**: преподаватель ведёт ситуацию, тренируется цепочка 112 → ДДС, группа участвует и разбирается. Основание — три дословные цитаты из «актуальности» ТЗ, которые обычно проскакивают мимо глаз:

> «...с управлением **ситуаций** с рабочего места преподавателя»
> «...обучать, развивать и совершенствовать навыки работы **диспетчерского персонала ДДС**»
> «...вывод информации на рабочее место преподавателя **и внешний монитор**»

Рамку несут четыре функции. Подробный технический разбор каждой — в [STACK-BACKEND.md](plan/STACK-BACKEND.md).

| Фича | Что даёт | Бэк | Фронт | Спринт |
|---|---|---|---|---|
| **Преподаватель-режиссёр** | Живые вбросы в ход звонка: паника нарастает, связь обрывается, второй пострадавший. Преподаватель — соавтор ситуации, а не зритель | 0.5 дн | 0.5 дн | 2 |
| **Цепочка 112 → ДДС** | Второй курсант принимает карточку, подтверждает за 4 с, может отбить на уточнение. Оценка выставляется паре | 0.5 дн | 1.5 дн | 3 |
| **Генератор сценариев** | Методист описывает происшествие словами — через полминуты игровой сценарий | 1 дн | 0.5 дн | 3 |
| **Агрегат ошибок группы** | Не оценка курсанта, а системная картина: что разбирать со всей группой | 0.5 дн | 0.5 дн | 3 |

**Чем платим,** чтобы объём — риск №1 — не вырос:

| Убираем | Взамен |
|---|---|
| Библиотека 15–20 сценариев → **8 эталонных** | Генератор |
| Уровни L1–L5 → **L1–L3** | Вбросы дают сложность живьём, а не списком |
| Эмоциональные вставки XTTS-v2 | Директива «паника нарастает» сильнее любого тембра |
| Тип вызова ЭРА-ГЛОНАСС | — |

**Ни одна из четырёх не стоит на критическом пути**, каждая вырезается в одиночку без последствий для сквозного пути.

## Календарь

### Спринт 0 — 15.09 (вт): каркас, контракт, проверка моделей

Единственный день, когда все пятеро работают над разным и ни от кого не зависят.

| Кто | Задача | Готово, когда |
|---|---|---|
| Лид | Вычитать открывшееся ТЗ, сверить с нашим разбором, выписать расхождения в `docs/TZ-DELTA.md` | Расхождений нет или они выписаны и разосланы |
| Архитектура | `backend/` поднимается, WS-эхо работает; GigaAM v3 RNNT и Silero v5 заведены на CPU, замерена задержка каждого этапа | Цифры бюджета задержки лежат в `docs/LATENCY.md` |
| AI | Клиент облачной LLM + кэш по хешу контекста; промпт персоны; `make repl` отвечает текстом | Диалог в консоли идёт, звонящий не выдаёт адрес без вопроса |
| Бэкенд-2 | `docker-compose` с Postgres, модели БД, alembic-миграция, CRUD сценариев | `make seed` заливает 1 сценарий, `GET /api/scenarios` отдаёт его |
| Фронт | Vite+React+TS, три роута-заглушки, WS-клиент, захват микрофона в 16 кГц PCM | Микрофон пишется, кадры летят на бэк, бэк их видит |

**Контракт фиксируется в первые 3 часа дня, до кода.** Архитектура + фронт садятся вдвоём, пишут [CONTRACT.md](plan/CONTRACT.md) и не расходятся, пока не подписан список WS-событий и модель КИО. Дальше меняется только через явный уговор — это единственный шов между треками.

**Гейт 0 (вечер 15.09):** GigaAM укладывается в 150–300 мс на финальном чанке на машине, которая поедет на питч. Если нет — немедленно смотрим CTC вместо RNNT, дальше Vosk; решение принимается в этот вечер, не откладывается.

### Спринт 1 — 16–18.09 (ср–пт): сквозной путь

- **16.09 — голос замыкается.** VAD → STT → LLM → TTS одной asyncio-цепочкой. Фронт: кнопка «Ответить», слышно звонящего, видно свою расшифровку. **Вертикальный срез по звуку.**
- **17.09 — карточка и таймеры.** Форма КИО по структуре норматива пишет в состояние сессии; серверные таймеры ГОСТ тикают и отдаются в UI; сессия сохраняется в БД.
- **18.09 — оценка.** Детерминированный слой (время опроса, полнота КИО, корректность ДДС, точность адреса) считается кодом, экран результата показывает разбор по пунктам со ссылкой на норматив.

> **Гейт 1 (вечер 18.09): сквозной путь на L1 работает end-to-end.**
> Не работает — по [DECISION.md](DECISION.md) немедленно переключаемся на предгенерированное дерево диалога (уровень A из разбора) и **не чиним реалтайм в ущерб остальному продукту**. Решение принимает архитектура, обсуждение — 15 минут, не полдня.

### Спринт 2 — 19–22.09 (сб–вт): три интерфейса, оценка целиком, вбросы

Первый полный уикенд — самый ёмкий кусок работы.

- **Трек A:** barge-in (локальный энергетический гейт на фронте + серверный VAD как авторитет, цель <150 мс), предгенерация первой реплики в WAV, филлеры при задержке >1 с, chunked TTS.
- **Трек B:** автомат слотов КИО (какие факты оператор добыл и какими вопросами), сверка с эталоном сценария, LLM-судья на мягких критериях — `temperature=0`, структурированный JSON с обоснованием по каждому пункту.
- **Трек C:** observer-поток по WS (пульт и монитор смотрят одну сессию), история сессий, API библиотеки сценариев с уровнями.
- **Трек D:** АРМ курсанта до боевого вида (казённое строгое оформление, полноэкранный режим), пульт преподавателя, каркас внешнего монитора.
- **Трек E:** 8 эталонных сценариев по классификаторам ДДС; тексты нормативных обоснований для каждой метрики.
- **Отрыв: преподаватель-режиссёр.** Канал `control`, восемь директив, свободное поле. Ставится **после** гейта 2, не раньше — пульт должен сначала работать как пульт.

> **Гейт 2 (вечер 22.09): занятие идёт на трёх экранах одновременно.** Преподаватель выбирает сценарий и запускает, курсант говорит, внешний монитор показывает ход разговора и заполнение карточки в реальном времени.
>
> Это база сцены питча. Дальше на неё встают вбросы преподавателя (сразу после гейта) и цепочка ДДС (спринт 3).

### Спринт 3 — 23–26.09 (ср–сб): Should-функции

Три фичи отрыва и то, без чего продукт неполон. Порядок внутри спринта — по убыванию ценности, режется с конца.

1. **Разбор после звонка:** транскрипт с подсветкой — где не уточнил адрес, где пропустил вопрос о пострадавших, где ошибся в классификации. **Для жюри-методистов это самое ценное: их ручная работа, автоматизированная.**
2. **Отрыв: цепочка 112 → ДДС.** АРМ диспетчера, подтверждение за 4 с, возврат карточки на уточнение, парная оценка. **Точка отсечения — вечер 24.09:** не стоит к этому моменту — режется целиком, без попытки доделать в ночь.
3. **Офлайн-режим:** дерево диалога на 8 сценариев в трёх эмоциональных вариантах узлов (чтобы директивы преподавателя работали без сети) + локальный матчинг эмбеддингами. Прогоняется с **физически выключенной сетью**, не «в теории».
4. **Отрыв: генератор сценариев.** Черновик из описания словами, эталон выводится из фактов кодом, публикует преподаватель вручную.
5. Уровни сложности L1–L3, включая обрыв связи с обратным дозвоном (3 попытки по 10 с).
6. **Отрыв: агрегат ошибок группы.** SQL и экран, без LLM.
7. Право преподавателя скорректировать оценку (дешёвая функция, сильная позиция: тренажёр готовит материал, а не заменяет преподавателя).

> **Гейт 3 (вечер 26.09): фиче-фриз.** После него в код идут только починки. Новая функция после 26.09 добавляется только по решению лида и только если она не трогает сквозной путь.

### Спринт 4 — 27–29.09 (вс–вт): сдача

- **27.09:** стабилизация, прогон всех сценариев подряд, деплой по публичной ссылке, README на три команды. Эксперт на заочке должен запустить прототип сам — это первый критерий выживания.
- **28.09:** видеоролик демо (сценарий из разбора кейса, 4–5 минут), презентация.
- **29.09:** финальный прогон, подача. **Сдаём в первой половине дня, не в дедлайн.**

### Окно доработки 16.10 – 29.10 (если прошли)

Питч 23.10, очно. Приоритет — не функции, а то, что нельзя отрепетировать заранее:

1. **Железо.** Гарнитуры, четыре машины, локальный сервер, прогон офлайн в зале. Целевая сцена — **три члена жюри в продукте одновременно:** один на гарнитуре как оператор 112, второй за станцией ДДС, третий за пультом преподавателя вбрасывает «связь обрывается». Четвёртый смотрит на внешний монитор, где идёт вся цепочка. Это наш главный козырь и наш главный риск отказа техники.
2. **Репетиции питча** по таймингу из разбора кейса (8 блоков, ~4.5 минуты).
3. **Фичи отрыва, не влезшие в спринт 3** — в первую очередь цепочка ДДС, если её резали 24.09. В окне доработки она стоит дешевле: контур уже стабилен, фронт свободен.
4. Что осталось из Could: тип вызова ЭРА-ГЛОНАСС, обёртка в Tauri. Эмоциональные вставки XTTS-v2 — только если вбросы преподавателя покажут нехватку выразительности; скорее всего не покажут. **SIP/Asterisk не трогаем даже здесь.**

## Definition of Done по Must

Функция считается сделанной, когда выполнено всё:

| Must-требование | Критерий приёмки |
|---|---|
| Сквозной голосовой контур | Задержка от конца реплики оператора до первого звука ответа ≤1.5 с, измерена, цифра в `docs/LATENCY.md` |
| АРМ курсанта с карточкой КИО | Все группы полей из норматива присутствуют; поля валидируются; заполнение уходит в БД и в observer-поток |
| Один сценарий от звонка до оценки | Прогоняется подряд 5 раз без ручного вмешательства и падений |
| Детерминированная оценка по ГОСТ | Каждая метрика отображается как «факт против норматива со ссылкой»: «опрос 94 с при нормативе 75 с (ГОСТ Р 22.7.03-2021)» |
| Пульт преподавателя | Выбор сценария, запуск, наблюдение в реальном времени без вмешательства в разговор |

## Дежурства по рискам

Каждый риск из разбора кейса имеет владельца, который следит за ним весь спринт — не «команда следит», а конкретный человек.

| Риск | Дежурный | Ранний сигнал | Что делает |
|---|---|---|---|
| Объём: 7 подсистем | Лид | Гейт пропущен | Режет Should, защищает сквозной путь |
| Контур не заводится | Архитектура | Гейт 1 | Переключение на дерево диалога, в тот же вечер |
| STT врёт на эмоциональной речи | Архитектура | Прогон на живых голосах команды 16.09 | CTC → Vosk → текстовый ввод как аварийный канал |
| Нет интернета на питче | AI | Прогон с выключенной сетью 25.09 | Дерево диалога уже готово, это плановый режим |
| LLM-судья нестабилен | AI | Разброс оценок на одном прогоне | temperature=0, усреднение 2–3 прогонов, вес 40% и не больше |
| Фронт не тянет четыре интерфейса | Фронт | Гейт 2 | Внешний монитор пишет лид. Если и этого мало — режется АРМ ДДС (точка отсечения 24.09), но **не пульт с вбросами**: он основной отрыв |
| Не дадут доступ к ПО системы-112 | Лид | — | Ничего. АРМ строится по открытым нормативам, доступ желателен и не критичен |

## Чего не делаем — ни при каких обстоятельствах

Из раздела «Won't» разбора кейса, вынесено сюда, потому что каждое искушение приходит в районе 20-го числа:

- Обучение любых моделей
- Whisper на CPU (23% WER для русского)
- Pipecat / LiveKit — свой пайплайн на ~300 строк дешевле чужих абстракций за две недели
- Локальная LLM 7B+ как основной путь
- SIP / Asterisk — веб-интерфейса с гарнитурой достаточно, это прямо сказано в разборе
- Точная копия боевого АРМ системы-112
