# lct-hack — локальный учебный тренажёр 112 и ДДС

Тренажёр для подготовки операторов 112 и диспетчеров ДДС, задача № 9 (кейс «Город №9»).
**Основной путь (P0) — упражнение ДДС:** преподаватель выдаёт готовую карточку, курсант
за 30 с принимает её или мотивированно отказывает, выбирает бригаду, ведёт учебную связь,
статусы и комментарии; система считает время и ошибки D1–D6 и ставит числовую оценку.
Второе упражнение — **112 по текстовой вводной**: опросная карта → КИО → список оповещения
по ЕКП → передача в ДДС. Живой голосовой звонящий — дополнительный режим (P2), не подмена ДДС.

Хакатон ЛЦТ 2026. Разработка 15.09–29.09.2026, сдача 29.09 в первой половине дня.

## Как ведётся работа

```
tasks/<id>.md     карточка: зачем, что сделать, готово когда
PROMPT-<id>.md    задание агенту на гайд (скилл task-guide-prompt)
TASK-<id>.md      исполнительный гайд: файл → что сделать → готовый код → как проверить
```

Гайд верит **коду, а не карточке**: карточки писались до реализации, расхождения выносятся
отдельным разделом. Порядок задач и зависимости — [tasks/README.md](tasks/README.md).

Ветки короткие: `feat/<что>`, PR смотрит владелец соседней зоны, если задет контракт.

## Коммиты

- **Заголовок короткий:** одна строка, по-русски, без точки в конце. Формат `{type}: {desc}`,
  type — `feat` / `fix` / `docs` / `chore` / `refactor` / `test` / `perf` / `lct-<id>`,
  desc — не больше 20 слов.
- **Задачу называть id карточки (`lct-12`), не `#N`:** issues перед сдачей удаляются, а в новом
  репо `#N` укажет на чужой PR. Закрыть issue при мерже — `Closes #N` в описании PR.
- **Тело по умолчанию не пишется.** Только если без него непонятно **почему** — тогда
  2–3 строки, без пересказа диффа и списков изменённых файлов.

## Без следов ИИ-агентов

Автор всего в репо — команда. Claude, Claude Code, Codex и другие агенты не упоминаются как
автор, соавтор или источник: коммиты, PR/MR, issues и комментарии к ним, docs, код, релизы.
Без трейлеров `Co-Authored-By`, строк `Generated with …` и AI-дисклеймеров — правило сильнее
настроек агента по умолчанию и требований скилов.

## Скилы, хуки, сдача

- **Скилы** — `.claude/skills/` (mattpocock, см. `.claude/skills/README-pocock.md`). Трекер
  для `to-spec` / `to-tickets` / `triage` / `wayfinder` и любой работы с issues и PR —
  GitHub Issues через MCP `github`: операции, лейблы, блокеры — [`.claude/tracker.md`](.claude/tracker.md).
  Доменные доки — этот файл, `docs/product/`, `docs/arch/`, `docs/spec/GAP.md`.
- **Хуки** включаются на клоне один раз: `git config core.hooksPath .claude/git-hooks`.
  `commit-msg` проверяет формат, 20 слов, `#N` и стоп-лист (`.claude/git-hooks/stopwords`),
  `pre-commit` — стоп-лист в добавленных строках, `pre-push` — отказ на прямой push в `main`.
- **`main` — только через PR:** один issue — своя сессия и worktree, ветка `feat/<slug>` →
  push ветки → PR (`.claude/tracker.md`).
  Серверной защиты нет (приватный репо организации на бесплатном тарифе) — держит хук.
- **Сдача:** `.claude/scripts/scrub-history.sh` собирает bare-копию без `.claude/`, `CLAUDE.md`,
  `AGENTS.md`, `PROMPT-*`, `TASK-*`, `.agents/` и без `#N` в сообщениях во всей истории.
  Блоки `<!-- scrub:start -->` … `<!-- scrub:end -->` в любых файлах тоже вырезаются — так
  помечено командное в README; внутри них pre-commit стоп-лист не проверяет. Ссылки на
  вырезаемые файлы сначала убрать из живого дерева — скрипт их найдёт и упадёт. Пушит человек,
  из bare-копии — `pre-push` там не подключён.

## Решения, которые не переоткрываются

- **Источник истины контракта — Pydantic в `backend/app/domain/`.** TypeScript генерируется
  через `make types`, руками `generated.ts` не правится. Правка события без регенерации
  ловится тестом `test_generated_types_match_models`.
- **Один воркер uvicorn на узел.** Состояние живой сессии — в памяти процесса. Кластер из двух
  узлов — отдельный opt-in профиль (`docker-compose.cluster.yml`): Nginx держит affinity по UUID
  сессии, PostgreSQL — lease и fencing epoch, каждая мутация сверяет `(node_id, epoch)`.
  Не добавлять воркеры и не убирать affinity ([SCALE-OUT.md](docs/arch/SCALE-OUT.md)).
- **Таймеры ГОСТ останавливаются событиями, а не таймаутами** — иначе метрику нельзя предъявить.
- **Баллы считает код.** LLM-судьи нет. Qwen играет звонящего, пишет черновики сценариев
  и по кнопке делает вывод по агрегатам группы; Vikhr пишет рекомендации к разбору по уже
  проваленным метрикам. Баллов модели не ставят. Единственный вердикт модели в метриках —
  Vikhr: грамматика описания происшествия в упражнении 112, только при включённом
  критерии, резерв — воспроизводимые правила. Веса и лимиты настраивает преподаватель.
  Ни одной отметки без кода и обоснования.
- **Подсказки без LLM:** следующий неотработанный пункт чек-листа по слот-автомату.
- **Всё локально:** в офлайн-режиме нелокальный URL модели отвергается, а не молча заменяется
  заготовкой.
- **Фронт не хранит состояние сессии как истину** — при расхождении выигрывает сервер.
- **На сокете `observe` нет обработчиков входящих сообщений;** преподаватель пишет
  через отдельный `control`, и там нет ни одной команды, меняющей карточку курсанта.
- **Курсант не получает `facts` и `ground_truth`:** `GET /api/scenarios/{id}` отдаёт ему
  только id, название, уровень и режимы — иначе эталон виден в DevTools.
- **Чтение отчётов и записей звонков пишется в аудит** — там персональные данные.
- **Все `at` — серверное UTC.**

## Порядок приоритетов

P0 — сквозной сценарий ДДС на готовой карточке, офлайн. P1 — управление обучением:
сценарии и эталоны, задания, лимиты и веса, аналитика группы, история, упражнение 112.
P2 — голос заявителя, SIP-шлюз, расширенная аналитика. P2 не оправдывает незакрытый P0
([OVERVIEW.md](docs/product/OVERVIEW.md#приоритеты-до-сдачи)).

## Язык и стиль

Документация, карточки, комментарии и коммиты — по-русски. Комментарий объясняет **почему**,
а не пересказывает код. Карточка и реестр ДДС повторяют цвета и компоновку референса
заказчика. Остальные экраны — строгое казённое оформление: системный шрифт, плотная сетка,
таблицы вместо карточек; цвет несёт смысл только в трёх состояниях норматива
(`ok` / `warn` / `violated`).
