# lct-hack — локальный учебный тренажёр 112 и ДДС

Тренажёр для подготовки операторов 112 и диспетчеров ДДС. Основной путь демонстрации задачи № 9: преподаватель выдаёт **готовые карточки** конкретной ДДС, курсант принимает решения за 30 секунд, ведёт статусы и комментарии своей службы и при необходимости использует локальный WebRTC/Asterisk для связи. Есть также отдельная текстовая вводная для оператора 112 и прежний голосовой вызов. [Рабочая спецификация](docs/spec/TZ.md) отделяет требования заказчика от учебных допущений реализации. Поток карточек ДДС реализован с настраиваемыми интервалом поступления и пределом ожидания; его браузерная приёмка ещё нужна.

## Подъём

```
make demo       MVP: база, готовые карточки, ДДС, учебная связь, фронт
```

Если порт PostgreSQL `5432` уже занят, используйте, например,
`POSTGRES_PORT=5434 make demo`: скрипт синхронно настроит контейнер и backend.
Для полностью контейнерного стенда порты также можно переопределить:
`POSTGRES_PORT=5434 BACKEND_PORT=8115 FRONTEND_PORT=5176 docker compose up --build`.

Для защищённого стенда используйте `make tls` и откройте
`https://localhost:5443/instructor`. HTTP-порт только перенаправляет на HTTPS,
API работает через тот же origin, WebSocket автоматически переходит на WSS,
а cookie входа получает флаг `Secure`. При первом запуске создаётся локальный
self-signed сертификат в `.local/tls`; браузер предупредит о недоверенном
издателе. Для учебного класса положите в эту папку выданные организацией
`tls.crt` и `tls.key`, соответствующие DNS-имени стенда. Публикация в локальную
сеть включается явно: `BIND_HOST=0.0.0.0 make tls`.

ИИ-формирователь открывается напрямую по адресу
`http://localhost:5173/instructor#ai-scenario-editor`. Войдите преподавателем,
выберите каркас, заполните описание, нажмите «Создать новый сюжет и эталон»,
затем обязательно «Проверить» и «Утвердить». Локальный Qwen запускается
отдельно командой `make local-llm`; без него редактор покажет явную ошибку, а не
выдаст шаблон за результат модели. Ответ модели проходит строгий серверный
JSON-контракт и детерминированные проверки ЕКП, обязательных фактов, адреса и
числа пострадавших; без успешной проверки черновик нельзя утвердить.
Compose-backend на macOS/Windows видит запущенный на хосте Qwen через
`host.docker.internal`; внешний URL в офлайн-режиме по-прежнему запрещён.

Дальше открыть пульт преподавателя — `http://localhost:5173/instructor`, выбрать упражнение «Готовая карточка ДДС» и открыть выданную ссылку на АРМ ДДС. Для режима 112 используется ссылка на АРМ курсанта. Модели для этого MVP не требуются. `make demo` не является доказательством холодного запуска без сети.

Необязательный эксперимент с локальным стеком Qwen3 1.7B + Vikhr 1B + Whisper small и перенос на
Windows описаны в [отдельной инструкции](docs/arch/LOCAL-MODELS.md). Он не является
условием работы ДДС; скорость STT на целевом сервере ещё не измерена.

Для проверки живого диалога именно локальным Qwen скопируйте
`backend/.env.test.example` в `backend/.env.test`, запустите `make local-llm`
и в другом терминале выполните `make test-llm-local`. Цель работает в offline-
режиме, отвергает нелокальный URL и падает, если модель не отвечает; тест
PostgreSQL-кэша отдельно требует доступной базы данных. Обычный `make test`
по-прежнему исключает долгие live-инференс проверки.

Для быстрого показа интерфейсов без Docker, БД и голосовых моделей запустите в двух терминалах:

```sh
make demo-lite
VITE_DEMO_MODE=true VITE_BACKEND_URL=http://127.0.0.1:8112 VITE_WS_BACKEND_URL=ws://127.0.0.1:8112 npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173
```

Откройте `http://127.0.0.1:5173/` и нажмите «Войти в демо одним нажатием». В пульте выберите упражнение ДДС или текстовую карточку 112, запустите занятие, затем откройте выданную ссылку на АРМ. Режим доступен только с локального компьютера; данные занятия, оценки и черновики редактора живут в памяти до остановки backend. История, групповая аналитика и голос в `demo-lite` недоступны. Полный режим с сохранением в PostgreSQL — `make demo`.

Чтобы попробовать ИИ-формирователь без Docker, сначала запустите `make local-llm` в третьем терминале. Затем на пульте преподавателя нажмите «Перейти к ИИ-формирователю сценария», выберите каркас категории и опроса и напишите описание. «Создать вариант ИИ» безопасно меняет часть сюжета; «Создать новый сюжет и эталон» заново формирует все ответы, адрес и число пострадавших внутри выбранного класса ЕКП. Черновик можно повторно изменить через поле «Комментарий для переработки». Проверьте предпросмотр и факты, нажмите «Проверить», затем «Утвердить». Новый сценарий появится в списке занятий. В `demo-lite` он исчезнет после перезапуска backend; в полном режиме хранится в PostgreSQL. Любая генерация требует проверки преподавателем.

Локальный стенд для разработки без голоса (карточки 112 и ДДС):

```
make dev           первоначальная сборка образов и запуск
make users-docker  один раз создать учётные записи внутри контейнера
make offline       последующий запуск без pull и build, из локальных образов
```

Эти команды используют пароль БД `lct` по умолчанию и предназначены только
для разработки на локальной машине. Для рабочего стенда в локальной сети
задайте в `.env` случайный URL-safe `POSTGRES_PASSWORD` длиной от 32 символов (например,
`python -c "import secrets; print(secrets.token_urlsafe(32))"`) и запускайте
`make production` либо `make offline-production`; оба варианта включают
обязательный пароль БД и HTTPS/WSS. `make production-config-check` проверяет,
что Compose откажется стартовать без пароля и передаст его PostgreSQL, backend
и сервису резервного копирования. При уже созданном volume `pgdata` изменение
переменной не меняет пароль пользователя автоматически: сначала выполните
ротацию роли `lct` в PostgreSQL и синхронно обновите `.env`.

Для переноса на машину без сети нужны заранее собранные образы и репозиторий: [пошаговая инструкция](docs/arch/OFFLINE.md). `docker-compose.yml` выполняет миграции и загружает сценарии при запуске. Наличие кода не заменяет живую проверку стенда на целевой машине.

## Что уже работает

| | |
|---|---|
| Голосовой контур | экспериментальный режим 112, выключен в MVP; после ответа обе стороны локально сводятся в WAV 16 кГц, доступный из профиля по правам; старые [замеры](docs/LATENCY.md) не относятся к выбранному Whisper small |
| Звонящий | в дополнительном режиме 112 использует локальную Qwen3 или Vikhr; при недоступности модели отвечает заготовками |
| АРМ курсанта | текстовая вводная и КИО без голоса либо приём голосового вызова, таймеры, подсказки и самооценка в режиме звонка |
| Пульт преподавателя | выбор упражнения, курсанта и сценария, локальный ИИ-редактор с предпросмотром, проверкой, утверждением, безопасным архивированием/восстановлением сценариев, наблюдение и директивы для голосового режима |
| Учебные материалы | преподаватель создаёт локальную текстовую памятку или загружает файл до 5 МБ, связывает с практикой и назначает курсанту/группе; курсант видит только назначенное и отмечает изучение |
| Внешний монитор | ход занятия крупно, после оценки — разбор на весь экран |
| АРМ ДДС | реестр готовых карточек, решение за 30 с, статусы и комментарии своей службы; выбор бригады и настоящий локальный WebRTC-звонок через Asterisk доступны как учебная связь, но не должны быть обязательным шлюзом статусов |
| АРМ администратора | учётные записи и роли, состояние стенда, живая нагрузка CPU/RAM/диска, очищенный отчёт об ошибках и сбоях, фильтруемый журнал действий с CSV-экспортом, резервные копии |
| Оценка | проверка действий по карточке и ДДС; принятые командой веса и нормы показаны отдельно от требований заказчика |
| Разбор и профиль | эталонные вопросы по пропущенному, расхождение самооценки, дельта попыток, скачивание отчёта CSV/PDF и сертификата PDF по сохранённым результатам |
| Аналитика группы | воспроизводимая статистика типичных ошибок и рекомендаций; по запросу — дополнительный локальный Qwen-инсайт только по обезличенным агрегатам |
| Конфигурация | администратор выгружает XML ролей, АРМ, таймеров, ЕКП и локальных моделей без секретов; отдельный сервис ежедневно снимает и ротирует восстанавливаемые копии PostgreSQL |

Краткий обрыв WSS не теряет неподтверждённые безопасные правки карточки:
клиент повторяет их после reconnect. Живой прогон с остановкой Nginx подтвердил
адрес сервером через 8,777 с; команды звонка и завершения намеренно не
повторяются автоматически. Подробности и свидетельство — в
[нагрузочных и аварийных проверках](docs/arch/LOAD-TEST.md#восстановление-браузерной-сессии).
Активная карточка ДДС также переживает аварийный restart одного backend:
контрольная точка в PostgreSQL сохраняет карточку, статус, выбранную бригаду,
ответ и таймер, а неизменённая учётная запись продолжает работу с той же
cookie. Это проверено отдельным
[crash-тестом](docs/arch/LOAD-TEST.md#восстановление-активного-занятия-после-перезапуска-backend).

Основные экраны адаптированы под телефон: автоматический Chromium-прогон
390×844 проверяет пульт преподавателя, карточку 112 и ДДС на отсутствие
горизонтального переполнения и сенсорных целей меньше 40 px. Скриншоты и
границы проверки приведены в
[разделе мобильной раскладки](docs/arch/LOAD-TEST.md#мобильная-раскладка).

Классификатор ЕКП, автомат статусов ДДС, групповая аналитика и локальный Qwen-формирователь сценариев уже есть. Локальный Asterisk поднимается командой `make sip`: абоненты 6001–6003 работают по SIP/UDP, SIP/TCP и SIPS, а браузерные 6101–6102 — по WSS/WebRTC; звонки записываются. [Проверка](docs/arch/SIP.md) подтверждает настоящий REGISTER, вызов, двусторонние аудиотреки и запись. Свежий изолированный loopback SIP/RTP smoke: регистрация, Echo-вызов и BYE успешны, 29 пакетов, p95 RTT **1,499 мс** ([результат](docs/evidence/sip-rtp-2026-09-25.json)); это не замер учебной LAN. Оцениваемый событийный протокол в АРМ ДДС сохранён отдельно: свободная речь в SIP-звонке пока не распознаётся и не оценивается. Сервер по ТЗ — от 6 ядер/32 ГБ без обязательной GPU. На локальном PostgreSQL/Nginx-кластере 20 занятий и 100 разных аутентифицированных пользователей прошли ramp-up 2 с: 100/100 страниц, p95 **1 017,12 мс**, ошибок маршрутизации нет ([отчёт](docs/evidence/browser-load-cluster-ramp2-pool20-no-prefetch-2026-09-25.json)). При нулевом ramp-up p95 **2 489,69 мс** — ориентир ≤2 с не выполнен ([отчёт](docs/evidence/browser-load-cluster-burst-pool20-no-prefetch-2026-09-25.json)). Целевое железо 6 ядер/32 ГБ ещё не испытано. Текущие пробелы — в [GAP.md](docs/spec/GAP.md), задачи разработки — в [tasks/README.md](tasks/README.md).

## Команды

```
make test       тесты бэкенда            make test-db    регрессия на временной PostgreSQL
make typecheck  проверка фронта
make test-voice голосовой контур на моделях   make latency    замер задержки по этапам
make seed       сценарии в БД            make migrate    миграции
make users      учётные записи ролей     make ekp        классификатор происшествий
make backup     резервная копия базы     make lesson     занятие и ссылки на экраны
make repl       диалог со звонящим без голоса и LLM
make back       бэкенд нативно, без голоса (сначала docker compose stop backend)
make sip        локальный Asterisk       make sip-test  SIP/RTP acceptance-test
make webrtc-test два браузера, WebRTC-аудио и запись Asterisk
```

`make test` запускает доступные тесты и пропускает PostgreSQL-интеграции, если БД недоступна. Для полного backend-прогона используй `make test-db`: он требует локальный Docker Compose и образ `postgres:16-alpine`, но создаёт отдельную временную БД и не трогает данные `make dev`.

## Для команды

Хуки коммитов на каждом клоне включаются один раз:

```
git config core.hooksPath .claude/git-hooks
```

`commit-msg` проверяет формат `{type}: {desc}`, лимит 20 слов, стоп-лист и ссылки `#N`;
`pre-commit` — стоп-лист в добавленных строках. Хукам нужен `bash`, скрипту
`.claude/scripts/scrub-history.sh` — `uvx`. Задачи в сообщениях — по id карточки
(`lct-12`), не `#N`: issues перед сдачей удаляются.

Issues и PR агенты ведут через MCP-сервер GitHub (операции — `.claude/tracker.md`).
Подключается у каждого своим токеном, один раз:

1. Токен: fine-grained PAT на репозиторий `GoatWhistle/lct-hack` с правами Issues,
   Pull requests и Contents — read/write. Если fine-grained на чужой репо выпустить нельзя —
   classic PAT со scope `repo`.
2. Регистрация на уровне пользователя — токен не попадает в репо:

   ```
   claude mcp add --transport http --scope user github https://api.githubcopilot.com/mcp \
     -H "Authorization: Bearer <токен>"
   ```

3. Проверка: `/mcp` в сессии показывает `github` подключённым; ошибка `403` — токену не
   хватает прав на репозиторий.

Блок между маркерами `scrub:start` / `scrub:end` вырезается из всей истории при сдаче.
