# Профиль и прогресс

## Зачем

«Контроль подготовленности» из ТЗ — не таблица оценок, а инструмент планирования
подготовки. Работа над ошибками становится измеримым циклом: разбор → повтор → дельта.

## Что сделать

- `GET /api/trainees/{id}/profile` и `GET /api/sessions/{id}/attempts`.
- SVG-радар шести компетенций, при нескольких попытках — динамика.
- История сессий с фильтром по режиму и периоду; самостоятельные помечены отдельно.
- **Дельта попыток по сценарию:** время опроса, полнота чек-листа, коды ошибок.
- Сильные и слабые стороны собираются из радара автоматически.

## Готово когда

- [x] Две попытки по одному сценарию видны с дельтой метрик
- [x] Контрольные попытки отделены от тренировочных
- [ ] Пометки преподавателя из всех сессий собраны в профиле

## Состояние

Сделано: `GET /api/trainees`, `GET /api/trainees/{id}/profile` — история попыток,
радар (среднее по попыткам), дельта между попытками по сценарию; экран `/profile`
с выбором курсанта, радаром, дельтой и историей со ссылками на разбор.

В отчёт занятия добавлена сводка числами (время опроса, добытые факты, подсказки,
коды ошибок): без неё дельту пришлось бы вытаскивать разбором текста метрик.

**Проверено сквозным тестом на живой базе:** два занятия одного курсанта дают две
попытки и посчитанную дельту.

**Не сделано:** пометки преподавателя из всех сессий в профиле не собраны — они
пишутся в журнал, но профиль их пока не читает. Сильные и слабые стороны словами
тоже не выводятся: радар есть, текста нет.

**Не проверено:** отрисовка в браузере.
