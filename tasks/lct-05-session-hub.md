# Сессия, таймеры, наблюдатели

## Зачем

Состояние живой сессии — то, что видят все четыре интерфейса. Внешний монитор включают
посреди занятия, и он обязан показать текущее состояние немедленно.

## Что сделать

- `session/state.py` — КИО, транскрипт, таймеры, режим, попытка.
- `session/timers.py` — старт и стоп **по событиям, не по таймаутам**; `timer.tick` раз в секунду.
- `session/hub.py` — реестр сессий и подписки наблюдателей.
- `api/ws/observe.py` — `session.snapshot` при подключении, дальше вещание.
  **Ни одного обработчика входящих сообщений на этом сокете.**
- `api/ws/control.py` — приём `scenario.start`, `session.stop`, `instructor_note.add`.
  Ни одной команды, меняющей карточку курсанта.
- `api/ws/call.py` — JSON-часть: `call.answer`, `kio.patch`, `dds.dispatch`, `call.hangup`.

## Готово когда

- [x] Подключение к `/ws/observe` посреди сессии показывает состояние целиком
- [x] Таймер `interview` стартует на `call.started` и останавливается на `dds.dispatch`
- [x] Правка карточки курсантом видна наблюдателю событием `kio.state`
- [x] Отправка сообщения в `observe` ничего не меняет

Подсказка пока идёт по порядку чек-листа, а не по неотработанным пунктам:
перевод на слот-автомат — карточка lct-14 после lct-07.
