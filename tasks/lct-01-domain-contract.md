# Домен и контракт

## Зачем

Единственный шов между треками. Пока `backend/app/domain/` не закрыт, фронт пишет заглушки,
а бэкенд не может отдать ни одного события. Контракт фиксируется **до** кода и меняется
потом только явным уговором двоих.

## Что сделать

- Довести черновик домена до контракта: `kio.py`, `events.py`, `timers.py`, `taxonomy.py`,
  `classifiers.py` (черновик уже в репозитории, писать с нуля не надо).
- Сверить перечень событий с `docs/arch/CONTRACT.md` построчно: ни одного лишнего,
  ни одного пропущенного.
- Уточняющие поля КИО по службам (01/02/03/04/ЖКХ) — проверить против
  `docs/spec/NORMATIVES.md`, дополнить недостающие.
- `make types` подключить в `npm run build` фронта, чтобы расхождение ловилось сборкой.
- Закрыть расхождение `mkh` / `gkh` в типе происшествия (см. «Расхождения» ниже).

## Готово когда

- [x] `make types` генерирует `frontend/src/shared/types/generated.ts`, файл компилируется `tsc --strict`
- [x] `make test` зелёный, включая тест «generated.ts не отстал от моделей»
- [x] Каждое событие из `CONTRACT.md` имеет модель, каждая модель — событие из `CONTRACT.md`
- [ ] Фронт и бэк подтвердили список событий и модель КИО (два имени в PR)

Выполнено в `TASK-lct-01-domain-contract.md`; открытым остаётся только подтверждение
двумя людьми — агент его поставить не может.

## Не входит

Реализация каналов WS, состояние сессии, БД. Только схемы.

## Расхождения в документации, которые закрывает эта карточка

- `SCENARIO-FORMAT.md` пишет тип происшествия ЖКХ как `mkh`, `CONTRACT.md` — код ДДС как `gkh`.
  В черновике домена принято `gkh` в обоих местах; если решение другое — правится и документ.
- `CONTRACT.md` не описывает payload `transcript.append` (в черновике — вложенная `TranscriptEntry`
  с якорем `ref`, без якоря пометки преподавателя некуда вешать).

## Датасет, 19.09.2026

Пункт «уточняющие поля КИО по службам (01/02/03/04/ЖКХ)» закрыт неверно — не по нашей
вине, а потому что классификатора тогда не было. В боевой карточке поля не привязаны
к службе: есть **опросная карта** (свободный текст), **формализованные признаки**
(три уровня) и **список оповещения**, который считается из признаков по ЕКП
([DATASET.md](../docs/spec/DATASET.md#памятка-по-арм-112)).

Домен от этого меняется: `DDSCode` перестаёт быть полем выбора и становится элементом
списка. Правка контракта — [lct-32](lct-32-ekp-classifier.md), она же перегенерирует
`generated.ts`. Расхождение `mkh`/`gkh` при этом теряет смысл: тип происшествия станет
кодом ЕКП, а не строкой.

Норматив `dds_ack` уже исправлен с 4 на 30 секунд — число в контракте было взято
по догадке со ссылкой на ГОСТ, где его нет.
