# Вход, роли, аудит

## Зачем

ТЗ называет три роли поимённо — администратор, преподаватель, обучающийся — и требует
разграничения доступа (RBAC), аудита действий и хранения журналов безопасности
не менее шести месяцев. Сейчас входа нет вообще: экраны открываются ссылкой с номером
занятия. Для прототипа это было удобно, для сдачи — самое крупное расхождение
([../docs/spec/GAP.md](../docs/spec/GAP.md)).

Разграничение у нас архитектурное — у наблюдателя физически нет канала записи, —
но не ролевое: кто угодно со ссылкой открывает пульт преподавателя.

## Что сделать

- Таблицы `users` (логин, хеш пароля, роль, блокировка) и `audit_log` (кто, что, когда, над чем).
- Вход по логину и паролю, сессия в подписанной cookie; хеш — `argon2` или `bcrypt`.
- Проверка роли на HTTP-точках и на всех четырёх сокетах: курсант не открывает `control`,
  обучающийся не видит чужие результаты.
- Аудит: запуск занятия, оценка, коррекция оценки, правка сценария, вход и выход.
- Экран входа и скрытие недоступных экранов по роли.
- Номер занятия перестаёт быть пропуском: по ссылке пускает роль, а не знание адреса.

## Готово когда

- [ ] Курсант не может открыть пульт преподавателя даже по прямой ссылке
- [ ] Преподаватель не может менять системные настройки, администратор не вмешивается в оценки
- [ ] Коррекция оценки и правка сценария попадают в журнал аудита с автором и временем
- [ ] Пароли не хранятся в открытом виде, журнал не пишет пароли и ключи
