# Голосовой контур

## Зачем

Критический путь всего проекта. Всё остальное наращивается поверх работающего контура.

## Что сделать

- `voice/pipeline.py` — четыре asyncio-задачи через очереди, отмена по `CancelledError`
  по всей цепочке сразу.
- `voice/vad.py` — Silero VAD, endpointing **600 мс** (не подбирать заново), детект barge-in.
- `voice/stt.py` — GigaAM через `onnx-asr`, режим по решению из lct-02.
- `voice/tts.py` — Silero v5 + SSML, чанки по предложению.
- `voice/audio.py` — PCM16, кадры 20 мс на вход (16 кГц), выход 24 кГц.
- `voice/prefetch.py` — предгенерённый WAV первой реплики и филлеры («алло?..» при задержке >1 с).
- Бинарные кадры по `/ws/call`, без обёртки JSON. `tts.cancel` при перебивании.

## Готово когда

- [x] Задержка от конца реплики оператора до первого звука ответа ≤ 1.5 с, **измерена и записана**
- [x] Barge-in гасит звук под 150 мс и отменяет LLM и TTS одним движением
- [x] Первая реплика играет мгновенно (предгенерённый WAV)
- [x] Прогон сценария 5 раз подряд без падений

## Состояние

Контур собран и замкнут: `voice/vad.py`, `voice/models.py`, `voice/text.py`,
`voice/pipeline.py`, подключён к `/ws/call`. Цифры — в `docs/LATENCY.md`, раздел «Контур целиком».

**Проверено:** ход 1.2–1.4 с, перебивание 88–90 мс, первая реплика 87–154 мс,
живой диалог через WebSocket 5 раз подряд без сбоев.

**Оговорки к галочкам:**
- задержка измерена **без LLM** — звонящий отвечает заготовками. На LLM до 1.5 с
  остаётся 100–300 мс;
- перебивание измерено в тесте контура напрямую, не через WebSocket;
- речь оператора синтезированная, из браузера с живым микрофоном контур не проверялся.

**Не сделано:**
- голос в контейнере — `make back` запускает бэкенд нативно с голосом, `make dev` — без;
- подача по настроению (SSML: скорость, высота) — синтез пока говорит одинаково;
- филлер «алло?..» написан, но ни разу не сработал: без LLM ответ готов быстрее секунды;
- звонящий на LLM — ждёт ключа, встанет за интерфейс `Caller`.
