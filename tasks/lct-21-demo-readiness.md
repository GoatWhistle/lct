# Готовность к сдаче

## Зачем

Сдаём 29.09 развёрнутый по ссылке прототип: эксперт запускает сам и ничего не ставит.
`make demo` пишется заранее, а не в последний день — командой, которой поднимают стенд,
надо успеть воспользоваться десяток раз.

## Что сделать

- `make demo` — офлайн, прогретые модели, засеянные сценарии.
- README с подъёмом в три команды: это первое, что читает эксперт.
- Прогон всех сценариев подряд в обоих режимах; поведение при обрыве WS; пустые состояния;
  экран «модели прогреваются».
- Проверка на **той машине, в том браузере и на том разрешении**, где пойдёт занятие.
- Видеоролик демо 4–5 минут и презентация.

## Готово когда

- [x] Один сценарий проходит подряд 5 раз без ручного вмешательства и падений
- [ ] Стенд поднимается на чистой машине по README
- [ ] Прогон с выключенной сетью пройден целиком
- [x] Цифра задержки измерена и записана в `docs/LATENCY.md`

## Состояние

`make demo` поднимает стенд целиком: проверяет модели, поднимает базу, накатывает
миграции, заливает сценарии, запускает бэкенд с голосом в офлайн-режиме и фронт,
печатает ссылки. Обкатан — и сразу поймал ошибку: `cd backend && команда &` уводит
в фон всю связку, родительская оболочка остаётся на месте, и фронт запускался
не из репозитория.

README переписан под фактическое состояние: два шага до стенда и таблица того,
что уже работает. Экран «стенд не в полной готовности» показывает курсанту,
почему звонящий молчит, вместо тишины без объяснений.

**Проверено:** пять диалогов подряд через `make demo` — без сбоев и ошибок,
ход 965–1210 мс, первая реплика 78–115 мс. `make dev` проверен целиком:
образ фронта собирается, страница отдаётся.

**Осталось людям:**
- поднять на чистой машине по README — здесь всё уже установлено, проверка нечестная;
- прогон с физически выключенной сетью: все модели локальные и офлайн-режим включается,
  но выдернуть кабель я не могу;
- прогон в браузере с гарнитурой на той машине, в том разрешении, где пойдёт занятие;
- презентация и видеоролик.
