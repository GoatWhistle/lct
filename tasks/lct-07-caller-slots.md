# Звонящий, который не выдаёт данные сам

## Зачем

Ключевая механика, отличающая тренажёр от чат-бота. Тот же автомат детерминированно
отвечает на вопрос «спросил ли оператор про этаж» — без него оценка полноты опроса
превращается в догадку LLM.

## Что сделать

- `dialog/slots.py` — автомат фактов: `question` через эмбеддинги (`multilingual-e5-small`),
  `approach` через LLM с бинарным решением. В контекст подмешиваются **только раскрытые** факты.
- Повторный вопрос по раскрытому факту помечается и уходит в персону как раздражение.
- `dialog/persona.py` — профили, эмоциональная дуга по этапам, состояние.
- `dialog/llm.py` — провайдеро-независимый клиент, стриминг, кэш по хешу контекста в Postgres.
- `dialog/prompts/` — промпты файлами, не в коде.
- `make repl` — текстовый диалог со звонящим без голоса. Работает до готовности lct-06.

## Готово когда

- [x] В `make repl` адрес не выдаётся, пока его не спросили
- [x] «На каком этаже?», «этаж какой?», «а этаж» раскрывают один и тот же факт
- [x] Повторный вопрос вызывает раздражение, а не второй вежливый ответ
- [ ] Скрытый факт не раскрывается прямым вопросом и раскрывается после эмпатии

## Состояние

Сделана половина без LLM: слот-автомат с матчингом по эмбеддингам, персона
с дугой и раздражением, звонящий на заготовках (`TemplateCaller`), `make repl`,
`make models` для эмбеддингов.

**Ждёт ключа LLM:**
- условие `approach` у скрытых фактов — метод `SlotMachine.reveal_by_approach` есть,
  решение «создал ли оператор подход» принимать некому;
- звонящий, говорящий своими словами, — встанет за интерфейс `Caller`;
- `dialog/llm.py` с кэшем в Postgres.

**Найдено при реализации:** одна формулировка на пункт чек-листа не отделяет вопрос
от не-вопроса на e5 — диапазоны близости перекрываются. Решение и цифры —
в `docs/spec/SCENARIO-FORMAT.md` (раздел про `examples` и `not_questions`).
